# 架构验证：复用现有执行回放串联许可修订

本轮验证架构连接及其整体作用，不添加新修订算法，不切换模拟器、不训练或调用生成模型。先写协议再运行。

**复用内容。**原 32 条连续执行序列、每条 12 次任务修订，共 384 次请求；复用原 successors 观测回放、无效果/其他合法动作扰动、历史契约、FragmentRuntime、来源 ready/静态缓存、独立动作下界及冻结来源片段。新增连接层只把已发出的许可修订建议，通过原 Runtime.accept 接回版本与票据管理，再继续执行原单步接口。

**权限和有限性。**同上一轮合成分流配置，明确允许每个物体 green/return 组双射，table 不变，锁定已完成/有争议 visit，不删除任何要求。许可是实验输入，不从颜色或失败推断。每次原任务请求至多发起一次修订搜索并采用至多一项建议，防止来回替换；最多 20 次动作尝试。need_observation 保持暂停，不以修订规避补证。本轮实际输出是符号动作，不驱动物理机器人。

实验调度器事先配置为采用第一项已核验的最小代价建议；这仅是本合成许可内的确定策略，不是为真实用户擅自改目标。建议必须绑定当前快照、版本与 generation；过期、篡改或重复采用应被拒绝。接回契约时只能改变许可组，执行历史和状态不变。原 ready 后缀核验和单步票据方法全部保留。

**主比较。**四组都拥有相同状态/完整历史、同一动作上界 H=8、同一许可、同一最小代价修订搜索、同一原完整规划器、下界、来源缓存与扰动规则。差别仅为失败库：standard 空库，fixed 旧十核心，source_partial 来源部分状态 nogood，learned 十八核心逐候选核查。目标阶段不学习、不扩缓存。要求主比较在动态采用修订后仍得到相同语义轨迹与完成结果，减少求解的收益才归于知识复用。

另设 no_repair 消融：保留完整失败库和可用配置，关闭修订建议采用。它用于说明连接修订模块后的行为变化，不冒充同功能的最强竞争基线；其轨迹可以不同。其结果应复现原既有回放的 197 次完成，按真实数据检查而非修改序列适配结果。

**计时和审计。**每组实际域构造、下界、缓存、库认证、桥接与修订连接准备均计费；执行循环包括建议生成、绑定检查、采用、后缀验证、命令和观测处理。3 次计时循环顺序，完整规划器调用分为运行时和修订搜索两项，不能漏掉后者。来源获取/建库历史成本不重新计入，只报告已有知识后的系统查询/执行回放费用。

所有独立原规划器参照判断、原 API 枚举的修订最优性、动作合法性、历史连续性和结果序列比较在计时外进行。观察来自确定的有限模型，不是 RGB 检测结果。ready 输出不得有历史违约；无效果观测不能写入预测完成事件；采用修订时不能改状态或账本。针对性测试另检验过期建议、重复采用、未知历史暂停和无许可情形。

**解释边界。**完成数按采用后的当前契约统计，同时单列未修订完成、采用修订后完成和失败，不把它们称为原始具体目标完成数。四个同功能组若完成数相同，架构收益体现在费用；no_repair 与主组的差异只证明此许可配置中的模块作用。完整部分 nogood 与 learned 的条件表等价事实保留，不据此宣称架构新颖性已确认或胜过已有完整机器人架构。已有 MuJoCo/MetaWorld 可作后续动作层验证，本轮不冒充其三物体感知控制已打通。
