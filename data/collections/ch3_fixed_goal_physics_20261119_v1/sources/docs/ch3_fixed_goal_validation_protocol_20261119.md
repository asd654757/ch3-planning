# 第三章固定目标仿真验证协议

研究问题：动作完成回执与事实不一致时，执行证据能否阻止错误状态传播，并在保留原任务目标的情况下重新执行？同样拥有证据和恢复能力的直接重规划保留为强对照。

固定任务为把蓝块放入绿色区域，最终空手。使用同一 MetaWorld/MuJoCo 场景、RGB 和机器人本体信息、固定路点控制器、接触后重抓门控、释放检查和终端几何评分。黄色及其他物体不在控制动作集合。每次重新创建场景，仅初始 reset。任何方法不得修改任务契约或把真值提供给在线策略。

开发种子为 1190。正式种子为 1201–1208。每种子配对运行四种预设条件和四个版本，共 128 回合。方法顺序随种子和条件循环。条件为正常、首次夹爪闭合命令失效、正常动作后首次观测遮蔽、首次夹爪闭合失效且观测持续遮蔽。受控故障只作用于首次抓取的夹爪通道或相机输入，动作或相机的故障在相同条件下对各方法相同。回执使用控制器原输出，不在测试中篡改。恢复可以通过新观测支持持物或已登记条件下的重抓，最多两次诊断观测、一次重抓、一次放置。后续不确定则停止，另设每回合 900 个在线控制步上限。所有失败与停止留在分母。

| 版本 | 接收的共同输入及允许的差异 |
|---|---|
| receipt | 回执消融。用正回执晋升内部预测持物，仍通过相同放置门控；门控拒绝后记录请求并停止，避免把未执行动作计为实际违规。 |
| no_recovery | 使用同一证据与调度接口，继承首计划，观察允许，但重抓关闭。 |
| direct | 使用同一证据、动作门控、原规划器与恢复预算。每个支持状态更新后从完整契约直接求解。 |
| routed | 使用同一证据和恢复预算。先验证剩余后缀，无法复用时调用同一规划器。 |

`receipt` 用于定位回执晋升这一机制的错误，不能作为唯一对照。`direct` 与 `routed` 的实际动作可能相同，应记录轨迹是否配对一致；规划次数下降只解释为减少完整求解，不能直接解释为机器人更快。

主要指标：独立几何判定的原目标完成，首次动作后假持物晋升、缺证据的放置请求、终端完成误报，持续缺证据时的有限停止。次要指标：恢复尝试、控制步、完整求解调用、规划与验证时间。几何真值在策略返回后读取，仅用于独立核验保存的边界事实和终端评分。开发样本单独保存。任何条件未产生预定失效的情形仍保留，同时单列实际故障覆盖。结论适用于登记颜色及闭合场景，未涉及开放世界或真实机器人的安全性。
