## 冻结范围

继续使用 fragment_three_fixtures_20261116_v2 的 384 条来源、768 条目标，原顺序、原预算 H=8、原 8 核心上限。不得新增目标、筛掉慢例、改变条款/动作/物体/下界或向学习组手工补核心。

保持直接重规划后端、核心删除最小化、变量规范化、适用条件语义、认证状态/绑定覆盖、编译匹配、缓存和在线 resolve 不变。修改仅在必要未来子任务的静态认证 oracle，两组都使用相同优化。

## 计算优化

1. 构造“合法物理状态×未来必经条款完成位”的有限图，移除会移动受保护物体的边；终点同时满足终态、空手和全部必经。
2. 从全部终点逆向 BFS，一次给出所有初始状态的精确最短距离。距离超当前预算/不可达才可判 conflict，不能将预算冲突写成永久不可行。
3. 同一图在所有物体重命名、两个相同容量区域互换下共享，桌面和手保持类型。每个查询仍按原始后继顺序重构后缀，保留原 BFS 的最短计划及并列选择。
4. 新 oracle 仅接收原有静态核心 Atom；完整任务、历史分支和执行仍调用原 decide。图构造、规范化、缓存、计划重构和新引擎初始化全部计时。
5. 新证书指纹包含新引擎源码；不直接信任旧指纹或未经核验的序列化表。载入时用新引擎重算全部字段。
6. 对已注册 Event 的六个不可变基础字段直接编码，减少逐步反射；其他数据仍使用原编码。输出字段和原证书逐项相同，编码费用计入，两组共同使用。

## 等价性与计量

- 先重算旧三物体来源的全部 18 个最终核心证书，逐项比较原状态、预算结果、完整动作后缀、绑定和冲突掩码；只允许引擎指纹不同。
- 与原规划器比较多预算、保护、空手、当前已占必经区域、桌面容量与并列最短计划。无误后运行计时。
- logical solve requests 仍计每个核心/状态查询；另计真实 profile 搜索次数、图节点与边。不能将接口查询直接称为被省掉的原后端调用。
- 两组独立处理同一来源，三轮串行交替，保存全部耗时与自动核心键。源任务本身真实回退数量必须与旧算法一致。
- 第一轮核心和缓存冻结；目标阶段不学习且缓存不增长。每轮从冻结源产物加载，重认证实际计时，不能复用上轮目标答案或上轮认证图。
- 目标三轮共同随机顺序，交替方法顺序。每个状态对照旧原搜索参考、每个 ready 后缀逐动作重放。复现旧额外覆盖 66 次以及三物体核心必要覆盖 47 次。
