# 同一在线接口下的失败约束获取与复用

本协议写于强对照审查之后。已知两类新增三条款核心及旧目标上的额外 336 次后端节省。后续是实现与成本复验，不是全新盲测；原审查的冷启动负结果保留。

## 本轮唯一改动

实现 FragmentSession：规则/认证片段匹配 → 精确缓存 → 原直接重规划器 → 仅 conflict 时自动提取和认证。规则组和学习组使用同一个类，区别只有是否开启学习。固定组一开始获得此前所有种子、六类专家规则及已知二条款预算规则。学习组不能手工获得这次新发现的两个三条款核心。

精确缓存双方从来源第一条请求起就能使用；保存原后端完整动作后缀。无历史且无 before 顺序约束才可使用共同静态特征键。对等价请求命中的 ready 后缀必须在计时外逐个重放核验，不将“只返回 ready 标签”当成可执行计划。原决策器处理所有未命中和历史请求。

## 固定过程

1. source 阶段仍使用旧 7,532 来源输入、种子 11661；禁止读取目标文件。各组独立运行真实在线过程，统计真实后端调用。三轮串行、组顺序交替，保留所有轮次。
2. 计时包括旧规则构建认证、每条请求的匹配、缓存、实际回退、学习提取和认证。输入加载费用共同计入。请求审计摘要、JSON 写入、额外删除见证和结果核查在计时之外，不把审查程序的重复匹配归为在线方法的成本。
3. 第一轮的库、缓存及自动提取核心冻结。其后三轮检查核心键和来源状态一致。将两组来源观察形成的缓存并集共同提供给目标阶段，合并费用共同计入。
4. transfer 独立调用；目标仍是旧 4/5 条款输入剔除已见来源签名后的 56,774 个组合。冻结同时禁止继续学习和目标缓存增长，避免重复计时因缓存目标答案而失真。
5. 三轮串行、相同打乱顺序、方法顺序交替。逐个对照已保存原后端状态，逐个重放 ready 后缀。计时不包括共同的核查和归档。报告每轮、查询中位数和完整一次性费用；总成本为来源构建/处理中位数＋实际载入重认证＋一次目标查询中位数。
6. 单独记录来源与目标真实调用，不能用假设的源调用数替代实测。核查运行源码、输入、证书与缓存哈希。原有历史/预算边界与全量回归必须通过。

## 解释边界

本轮可检验真实在线接口的计算费用，不能把回顾性旧组合计时写成新任务独立验证。无新增语言模型请求、物理实验、机器人成功率、开放世界保证或新颖性认定。不因正负结果再更换来源顺序或目标子集。
