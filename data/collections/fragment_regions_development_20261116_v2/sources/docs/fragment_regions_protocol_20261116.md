# 条件泛化后的冲突片段：开发与新组合验证协议

本协议在四/五条款新组合的任何结果计算前冻结。主题仍是失败经验的可验证提取和同域复用；不更换模拟器、机器人技能或任务成功定义，不训练或调用模型。

## 已见开发数据与冻结来源

此前 55 个真实模型拒绝、9 个案例，及 7,532 个已查看的有限组合/边界输入均作为开发资料。它们不再计为新验证样本。固定随机种子 613 从这批旧输入中抽取 256 个作校准请求；顺序在处理前固定，不按冲突标签挑选。

初始核心从真实拒绝来源自动删除条款得到。校准中，既有片段/规则未命中时实际调用同一 8 步求解器；只有它返回 conflict，才尝试提取新核心。历史松弛可行则弃权；最多添加 8 个核心族。不读取旧结果标签决定新增规则。开发实际新增 1 类核心，涉及终态占用与另一物体待完成必经的联合 8 步约束。来源是符号规划后端返回不可行，不能称新增机器人执行失败。

冻结训练目录 `fragment_regions_development_20261116_v2` 保存模式、校准流与各组证书；验证直接读取并重新认证，不在新组合上继续学习、选择规则或调整参数。全部输入与证书运行前保存哈希。v1 是开发记录；在新组合运行前修正 JSON 载入时 tuple/list 的表示比较，补充真实 JSON 往返检查，重新构建 v2，不改校准输入或规则。

## 条件泛化与共同编译器

对一个小任务核心，枚举注册领域中全部 13 个状态和类型变量绑定，记录核心在哪些状态中不可行。这是相对于该核心和该有限领域的最大冲突状态集合；每个绑定单独核验。目标类型扩展至所有注册目标，table 的容量仍不同，不能因名称相似而强加冲突。

所有编译组采用相同的状态索引、位集合匹配、子集消去、必要条件闭包、运行中语义检查和回退求解器。未满足的 at(x,r) 蕴含未来需要 place(x,r)，这条领域蕴含同等提供给每组。更改正在执行的语义函数、字节码或领域常量使会话失效；未经重载的磁盘编辑不改变正在执行的 Python 语义。外部证书载入须重新计算，不能只相信哈希或自报 verified。

共同强规则来自六类人工核心：终态容量冲突、同物体不同终点、保护与终态移动、保护与自身必经、保护物体占用另一物体必经/占手、持物保护与空手要求。它们使用相同求解器认证状态条件，较 v1 的简单规则更强；保护对象占手的阻碍已包含。它不是穷举所有可能复合任务的专家知识上界。

## 四组与主要指标

1. recompute：每次用原有求解器判断。
2. expert：强规则核心的最大状态条件＋共同编译器＋未命中回退。
3. seed：expert＋从原 55 个拒绝提取的初始核心；隔离仅放宽原经验的收益。
4. learned：seed＋旧校准流中自动新增的核心；这是主方法，主对照为 expert。

同一查询的预算、领域、任务、状态、历史和输出三态一致。新验证全部用原求解器交叉检查，不正确拒绝一个可行/缺证据任务就不宣称正确性保持。没有用学习结果替换模型动作或增加一组独享的诊断信息。

主要确定性指标：三态完全一致、误拒、后端真实调用次数。主要运行指标：相同序列的完整批次墙钟/CPU 时间，及**包含构建/校准/重新认证**的冷启动总成本。只减少调用但总计时更差，不称总加速。已知领域模型、人工作规则的工程成本分别说明，不凭未计入的人工成本宣称优势。

## 尚未运行的新组合

条款池沿用旧版 15 个原子：两物体×三目标的 at/visit、两物体的 forbid、empty。完整枚举恰好 4 条和 5 条的组合，交叉全部 13 个合法状态：17,745＋39,039＝**56,784 个唯一输入**。与开发至多 3 条的组合不同；同时仍是同一有限领域的系统覆盖，不是 56,784 个独立机器人试验或开放世界泛化验证。

新组合的标签不参与构建条件。五轮完整计时，随机种子 7361＋轮次改变共同查询顺序，各方法顺序轮转。单进程串行，不在计时期间运行其他本任务测试/分析；输出写盘在计时外。同一批重复五次只用于计时稳定性，不增加独立样本数，也不合并重复批次来虚构冷启动摊销。

冻结完整每轮计时和全部唯一输入的原求解状态，不删失败或最慢轮次。所有组必须完全一致。先报告每轮、再报告中位数；样本是软件计时轮次，不作机器人成功率显著性检验。

冷启动 learned 的成本包括开发记录中的完整准备时间（55 个旧拒绝重放、初始提取、专家和学习核心认证、256 条校准及未命中回退）＋本轮证书重新认证＋一个新批次时间；expert 包括专家构建＋本轮专家重认证＋一个批次时间。若只在热启动下更快，明确报告冷启动不占优，不把五轮重复当作新工作负载。

## 结论边界

若离散调用数严格减少且每个结论都与原求解器相同，可证明本有限输入空间上的求解调用减少。若包括准备成本的同批总成本也低，才称本工作负载下有冷启动计算优势。它不等于真实机器人成功率提高、LLM token 减少或已具备投稿新颖性。

主张限定为：在已注册领域和任务预算下，从旧失败自动提取复合冲突核心，认证其适用条件后，减少新任务组合的重复求解。不能把一般缓存/位运算优化本身包装为新的规划理论，也不能声称人工可以编写的任何规则均无法达到相同效果。
