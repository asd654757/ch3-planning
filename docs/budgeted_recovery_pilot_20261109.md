# 预算恢复开发对照：版本与判据

## 范围

这是严格协议的独立开发分支，不是正式优效实验，也没有复现LLM直接重规划。
固定恢复控制器，在线实际执行观察、继续放置、接触前回撤重抓并完成任务。
接触后的空手/重抓授权仍缺失，不能把该条件改成可恢复或删掉。

初始故障交叉：normal、temporary（首轮反馈缺失）、delayed（前两轮缺失）、
persistent（始终缺失）、precontact（接触前20步超时＋首轮缺失）、
released（主动开爪释放＋首轮缺失）。外部传感器故障按采集序号施加，
不是连续物理时间或自然故障持续性；策略不能读取这些标签。

可见家族仅由公开控制回执及命令历史确定：post_pick/precontact/released。
恢复概率模型是“已发生多少轮unknown”的经验条件危险率，不是完整开世界
隐状态模型。全部方法获得相同RGB、回执、命令、预算和共享执行门槛。

  所有结果保留。动作成本上限被同时用于未来资源推演，可能过早拒绝可完成路径。

## v3改动（在v3运行前写定）

1. 宏动作最大可用成本仍为开发集最大显式控制步×1.25向上取整，所有方法
   一致；执行超过这个cap即中断并保留失败。实际已耗控制步更新运行预算。
2. 前瞻分支根据开发记录的观察结果/耗时联合分布更新未来预算，不再把cap
   当每次实际消耗。对平滑后未观察过的结果，时长先验用同状态已观测时长池。
3. rule基线增加与前瞻共享的后续完成资源信息，避免只能靠缺少预算判断的
   弱规则获胜。观察次数阈值0–3在开发模型上调优，pilot前冻结。
4. depth1/depth2使用相同模型、资源边界和经验rule-3边界价值。边界价值只
   是近似延续估计；有限深度仍可能低估/高估超出范围的恢复。
5. 纯成功率目标，动作loss设0，不通过调成功/成本权重来制造胜差。
   实际成本单独报告；无成功机会时提前停止不计任务完成。

## 预算和估计来源

三档控制步预算由开发cap推导：continue cap、continue+2×observe cap、
retry+3×observe cap；额外观察上限4、命令上限2、API预算0。
每次决策首先验证共同权限及宏动作cap能否支付，再计算价值。
初始执行和独立末端10步评分作为共同开销另记，不占恢复预算。
观察包含实际探测运动；重试宏动作包含回撤、新绑定、重抓、新观察与放置。

概率用开发计数和Jeffreys Beta(.5,.5)平滑，保留计数。这不等于充分概率校准，
不提供未知故障的鲁棒保证。宏动作完成奖励来自独立几何评分，不来自控制回执。
样本小、同一固定场景、受控传感器缺失，不称开放世界验证。

## 输出和停止

报告每档预算、每种条件及总体配对原始成功数、停止与失败、实际恢复步数。
一切状态/解析/执行错误保留；计数不全不得宣称完成。
若depth2与调优规则及depth1持平，就报告本任务尚未证明前瞻收益；
若只节省不可能完成条件中的观察，需说明这是预算门控作用而非多步前瞻。
本pilot之后不按结果增加seed寻找显著性；先审查是否存在真正不同的恢复路径。
