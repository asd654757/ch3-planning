# 第三章历史规模实验的交错计时复核

复用四种算法、八种规模配置和每组的 24 个决策。八轮中，每轮运行全部八种规模，每种规模在八个运行位置各出现一次。每种规模内交错运行四种方法，进程固定在逻辑 CPU 0。逐例判定及计划的全历史有效性与归档结果一致。

下表为每组 24 次决策的累计耗时中位数，单位 ms。

| 物体数 | 未知事件数 | 逐分支核验 | 同历史重规划 | 基础版 ROUTED | 候选优先 ROUTED |
|---:|---:|---:|---:|---:|---:|
| 3 | 1 | 10.21 | 14.24 | 12.40 | 9.97 |
| 3 | 2 | 21.90 | 54.54 | 51.65 | 21.01 |
| 3 | 3 | 43.09 | 209.91 | 202.96 | 39.61 |
| 3 | 4 | 57.09 | 483.19 | 476.50 | 52.62 |
| 4 | 1 | 11.93 | 17.01 | 14.99 | 11.83 |
| 4 | 2 | 26.16 | 68.65 | 63.18 | 25.08 |
| 4 | 3 | 50.15 | 257.82 | 252.88 | 50.60 |
| 4 | 4 | 66.55 | 594.89 | 578.12 | 59.68 |

原先在固定未知事件数下增加物体反而更快，以及三物体组中第三至第四个未知事件之间的耗时回落，在交错复测中均未重现。另行运行相同的搜索，记录各任务族从搜索队列取出的节点数。三物体组的六个补做检验案例中，候选优先 ROUTED 在三个和四个未知事件时分别取出 1653、2036 个节点。这个计数包含因约束或重复状态被筛掉的节点。结果支持将原耗时回落视为对计时安排或运行条件敏感的现象，数据未采集 CPU 频率和后台负载。

各方法在八种配置上均判对 24/24。四物体、四未知事件时，候选优先 ROUTED 相对基础版的中位耗时下降 89.7%，相对逐分支核验下降 10.3%，后者的同轮配对有 8/8 轮更快。候选优先 ROUTED 在八种配置中的七种具有较低的耗时中位数，四物体、三未知事件时的中位耗时为 50.60 ms，逐分支为 50.15 ms。各轮配对时间保存在原始数据中。

## 复现

```bash
PYTHONPATH=. python scripts/audit_ch3_interleaved_scale.py --cpu 0 \
  --reference data/collections/ch3_candidate_first_20261124_v1/history_scale.json \
  --output /tmp/ch3_interleaved_scale.json
```

`--cpu` 应选择运行环境允许的逻辑 CPU。逐轮数据保存在 `data/collections/ch3_candidate_first_20261124_v1/interleaved_scale.json`。
