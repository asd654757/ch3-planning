# v8 被拒绝候选的条件修复小试

主题：大模型机器人剩余任务规划的确定性验证与修复。仅评估规划，不调用控制器、不引入评分真值。

冻结来源：v7 development、v7 budget units、v7.2 三个已归档目录。纳入其中所有可解析、非初始、原被拒绝且当前 v8 执行契约仍拒绝的真实模型候选；按 v8 当前观测快照、候选、图像哈希去重。不按后续方法成功与否选样。冻结 manifest 含 16 个不同输入，无排除项。它们来自开发数据，不能作为独立泛化或自然失败率证据，亦不保证统计独立。

比较 DIRECT_REGENERATION 与 CANDIDATE_ERROR_REVIEW。共享同一当前状态、目标、历史、图像、剩余执行预算、模型参数和验证门。两者各额外调用一次；前者直接重新生成，后者额外得到未执行的候选及其具体违反约束。奇偶点交替请求顺序。温度 0.1，模型 seed 0，1024 输出 token，API 自动重试 0。没有程序生成正确动作、自动排序或计划替换。被拒绝候选不更新观测状态。

主指标：一调用后完整剩余计划接受率；记录直接独有/反馈独有成功、具体拒绝原因、真实调用与 token。接受需要 Validator、目标、保护对象、空手、占位和全局剩余执行预算同时通过。不是物理任务成功率。

对照是“重新生成”与“候选+具体错误复核”的组合比较，不能单独归因于错误解释（候选内容也不同）。如果需要分离两者，另行预注册候选无错误说明对照，不事后改本批定义。

v8 formal 中 medium/hard 各 30 配对，两方法各 29/30，没有候选拒绝或配对差异，因此证明执行恢复稳定性，不证明候选复核的增量收益。本批条件实验不能混入 formal 分母，也不能消除这个负结论。
