# 接近阶段超时后的持续场景恢复：单例诊断

## 实现

新增 `--recover-early-pick`，仅配合完整初始模型规划使用。授权仅限：受控初始空手前提、控制器报告 phase 0 超时且未执行下降/夹爪闭合、目标在新 RGB 中可见且相对初始漂移不超过 3px。phase 1/2/3、缺失图像或目标变化不授权。阶段轨迹是在固定后端与受控无外部事件假设下的过程证据，不是力觉接触传感或普适无接触证明。

授权后有界竖直回撤，夹爪打开；完成后再次读取图像并复核目标，再调用模型生成当前状态的完整剩余 pick/place 计划。失败时停止，不无限重试。回撤只是固定场景的工作空间启发式，不是碰撞安全保证。

这里当前剩余任务仍是整个运输任务，因为第一次 pick 尚未完成。状态来源明确记录为受控初始前提在接近阶段轨迹下保持，**不是视觉空手估计**。模型计划在 Validator 与预测目标检查后编译；后续真正抓取后仍依赖共运动持物证据才规划 place。

## 贡献归因与边界

这是人为压缩执行预算的单例，证明了持续场景恢复路径可执行，不代表自然失败率或一般抓取恢复。未覆盖闭合后的掉落、抓错物体、复杂遮挡或开放世界。

当前重规划与初始计划动作相同，固定回撤加重试可能同样完成。因此不能声称此例证明大模型必要性或规划修复优于程序重试。还需要相同故障起点比较无恢复、固定回撤重试、当前状态模型重规划；固定重试应使用相同观测和控制预算。若它同样成功，则报告模型调用开销，不事后筛去该结果。

还需测试目标变化时的重规划，但现阶段目标变化会安全拒绝，因为尚未建立足够的更新状态证据。不能为制造性能差距删除这条保护。先冻结协议并补拒绝控制，再扩少量 seed，不直接全量运行。
