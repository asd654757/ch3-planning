# 持续场景剩余任务重规划：等信息等预算 pilot v3

主题保持为大模型机器人任务规划与反馈修复，不增加控制器训练或感知算法。

## 固定条件

- 当前双物体、双区域持续场景，seed 58、59、60、61、62、63；两种方法共 12 次执行。
- 首次观测支持的交付后显式交换两个目标；属于受控任务更新，不称为自然物理执行故障。
- 同 seed 共享初始模型输出，并验证初始请求和图像哈希完全一致。
- 方法顺序随 seed 奇偶交替。后续图像源于各自真实执行，不声称不同轨迹的图像完全相同。
- 相同图像入口、当前符号事实、执行历史、目标、已完成对象保护、模型参数、控制器、评分阈值。
- 两种方法均保留 Validator、Goal Checker 和后端契约；不得为了对照故意执行危险或无效计划。

## 唯一区别

- MODEL_DIRECT_REPLAN：发现旧后缀失效后，让大模型从当前状态重规划；不提供校验错误细节。
- MODEL_CONSTRAINT_REPAIR：同样重规划，但提供校验器拒绝原因；若模型输出再次被拒绝，后续请求更新拒绝原因。
- 共同最多两次非初始请求；第一次合法即可执行，不为了凑预算强制调用。初始纠错也占共同非初始预算。
- v3 将被拒绝的剩余候选重试接入相同预算。它不同于 v2 单次剩余请求路径，不能跨版本当作严格消融。

## 评价

报告最终任务成功、实际调用/消耗、拒绝原因、实际执行的修复次数、共享初始输入检查。小样本只作机制与可执行性核验，不作显著性能结论。

如果两种方法都成功，不人为引入格式错误、不筛选失败 seed、不降低对照预算；诚实说明简单任务更新下错误反馈没有可测增益。下一阶段应检验真实执行偏差与更复杂剩余约束，但仍需先验证观测与故障恢复接口，而不是直接扩大次数。

评分真值仅用于终端评价，禁止用于动作授权或修复触发。当前已知颜色与初始 fixture 的限制保持不变。
