# v6 反馈结构：权威任务与诊断证据分离

## 动机与边界

v5 正式任务更新对照中反馈方法 41/50、直接重规划 50/50。被拒绝候选的预测状态与局部缺失目标可能造成补丁式锚定，这是待检验解释，不是已证明的唯一因果。

本修改仅针对大模型剩余任务规划与校验反馈，保持环境、控制器、评分阈值、两次非初始调用预算及安全门不变。没有新增视觉定位模型或程序代写动作。

## 请求结构

1. 当前事实、全部目标和全部剩余目标仍是唯一权威任务信息。
2. current_task_obligations 给每个对象明确列出观测位置、要求区域与是否还需要交付；终态要求明确列出空手。这些信息对直接重规划和反馈修复同时提供。
3. 模型反馈仅含拒绝类别、漏目标数量、未执行标志及完整重新规划提示。**不发送**局部缺失目标列表、预测终态、被拒计划或原始输出。
4. 完整拒绝证据留在 local_feedback_evidence 与 rejection 审计中，供离线分析；不当作当前状态传给模型。
5. 每次重试保持观测状态与已执行历史不变。拒绝计划绝不推进状态，接受也不假定执行完成；只有已有 RGB 释放与目标支持事件更新执行历史。

此版本并非取消错误反馈，而是把详细证据保留给程序审计，将模型可见反馈限制成诊断，避免用上一候选定义下一次任务。对动作前置错误仍给类别与重检契约提示；若过度压缩降低纠错能力，应作为新负结果记录，不承诺必然提升。

## 验证顺序

- 单元测试验证漏目标仍被拒绝、预测状态与候选不进入请求、两方法任务输入相同、拒绝不推进状态与调用预算相同。
- 先对原正式失败 seed 72、73、80 做已知失败回放；只评价新候选接受情况，不作为执行成功率或新方法优越性的证据。
- 回放若可行，再冻结独立小规模 seed 做真实执行评价；本次不自动启动大规模实验。
- 旧 v5 正式数据永久保留，新数据不混入原分母。

正式物理故障恢复接口尚待验证；此处仍是任务更新剩余重规划，不可称为自然执行故障或开放世界视觉恢复。
