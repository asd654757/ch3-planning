# 当前环境的可变合法后缀与任务更新pilot

本阶段不换环境、不训练控制策略、不新增第三物体。核心为真实大模型计划不再对照固定序列答案，而按当前目标、状态、后端能力与禁动约束接受不同合法顺序。

## 新接口

- FlexibleFixturePlanner独立版本，旧SequenceModelPlanner不变。
- 状态由已支持的实际释放事件更新对象位置，保留具体对象历史，不由完成阶段编号推断。
- 初始物体/区域注册仍为受控fixture，观测RGB持物/释放/目标检查仍有限，不是开放世界感知。
- 可接受任意顺序的相邻pick/place搬运；限两个可移动物体、两个区域、总计最多4次搬运、最多2次修复调用。相邻配对属于现有后端契约，不是预设计划答案。
- 保持满足当前目标的已完成对象不被再次操作；任务显式变更后，不再满足新目标的旧交付可重新搬运。这不是重放历史命令，而是新的剩余目标。
- 静态区域初始RGB参考、释放/目标分开检查、未知停止、独立评分不反馈模型，沿用feedback-v2。
- 暂不复用旧执行故障恢复分支：新接口先验证任务变化后的规划与执行。不能称为自然执行失败恢复正式结果。

## 冻结pilot

两个独立批次，seed均55、56、57，每批两个设置共6次。

1. stable：初始蓝色返回区域、黄色绿色区域，顺序由模型决定，验证非固定顺序执行与证据历史。
2. goal_update：首次支持的交付后显式交换两个对象目的区域；两设置同时获得新目标，不修复设置校验旧后缀后停止，修复设置请求实际模型生成剩余后缀。

模型候选在同seed共享，设置顺序交替，环境实际连续执行。任务变化是预先声明的受控指令变化，不是自然失败。无修复对照预期无法适应变化，故即使成功率差大也不能证明本框架优于普通模型重规划；下一轮须加入同信息同预算直接模型重规划/符号规划对照。

门槛：stable具备可执行性，goal_update实际模型修复接受并执行完成，日志状态/目标更新一致，无固定答案替换、无真值授权、无历史已完成对象误保护。未通过门槛不扩量。

本阶段先实现可变顺序与剩余目标变更；一般先后顺序约束、三物体和未知支撑状态估计尚未完成，不能声称均已支持。
