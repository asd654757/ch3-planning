## v2 结果

| 条件 | 不修复剩余任务 | 约束检查后大模型修复 | 实际 API 调用 |
| --- | --- | --- | --- |
| 目标保持不变 | 3/3 | 3/3 | 3 次共享初始规划 |
| 首次交付后显式交换两个目标 | 0/3 | 3/3 | 3 次共享初始规划 + 3 次剩余任务修复 |

两个条件共 12 次持续场景执行、9 次实际模型调用。更新条件下三个配对都共享同一初始候选，初始候选全部接受；修复方法三个剩余请求全部接受并执行完成。无修复方法均在首次成功交付后发现旧后缀无法满足新目标，安全停止。没有初始缓存不一致或额外初始纠错。

更新条件每个成功轨迹包含三次实际搬运：第一次旧目标交付，随后两个新目标交付。不是重置 episode 后重演已完成历史，而是从观测支持的位置继续规划新的剩余任务。

## 能支持与不能支持的结论

可支持：现有环境能接入真实大模型，接受符合约束的可变动作顺序，在同一持续场景里根据成功交付历史和显式任务变更生成并执行剩余计划。不是没有模型调用的程序规则演示。

不能支持：正式性能优势、自然执行失败恢复率、开放世界视觉状态估计能力、优于普通大模型重规划或符号搜索。任务变更是预先声明的受控条件；不修复对照无法适应新目标是预期结果，不应将 3/3 对 0/3 包装为算法显著优势。

## 下一步正式实验门槛

1. 加入同当前状态、图像、目标、后端和调用预算的直接大模型剩余重规划参考，区分“允许重规划”的收益与约束反馈机制的收益。
2. 小规模验证模型拒绝后的纠错路径与真实执行失败的反馈路径；当前 flexible pilot 禁用了旧版物理故障恢复分支，不能据此宣称已验证。
3. 冻结任务条件和 seed 后再扩量；保持评分真值仅用于评价，未知观测停止，不用降低评分阈值或选择失败 seed 制造差异。
4. 仍使用当前环境和固定技能后端；不扩展为控制策略训练或新的感知项目。
