# 收束验证：显式目的许可下的成组目标替换

本轮只完成一种有明确边界的替换算子、正确性审计和强对照，然后整理章节方案。不因结果小或为负继续扩算子、换任务或追求百分比。旧协议和实验不变。

**语义许可是新增实验输入。**在合成的分流/暂存配置中，为每个物体明确声明 green 与 return 均为允许的同类单位容量暂存位；table 不属于这一类。该声明不是从颜色、历史、规划失败或语言模型猜出的，也不表示真实 green/return 场地天然等价。对原冻结任务附加同一许可，属于受控任务变体，不是原任务成功率实验。

替换必须按同一物体成组进行：该物体所有 at/visit 中的 green/return 同时互换。因此原来相同的目标仍相同，原来不同的目标仍不同，不会把两个不同途经目标合并。物体、条款 ID、kind、before 引用、forbid、empty 以及条款数量全部不变。table 要求不变。不允许删除、加要求、换物体或改过去。

若物体相关的 visit 已有有效时间之后的 confirmed 或 unknown 放置证据，锁定该物体的替换，避免重解释已完成或有争议的要求。未改要求的 since 保持不变；真正改变的要求按原 apply_replacement 语义从当前 cursor 生效。历史账本和当前状态保持不变。替换许可绑定 snapshot.digest，旧许可不能用于新快照。

优化目标为改变条款数最少，再按 `(条款 ID, 新目标)` 排序；各组枚举相同组替换集合，原非 ready 判定为共同输入。只返回建议及经原模型验证的共同后缀；无可行替换时明确返回 no_permitted_substitution。

**工作负载与对照。**复用全部 187 次连续执行失败和全部 432 个既有静态目标失败，不按本轮结果选例。H=8。比较：

1. 标准最小代价枚举；
2. 相同枚举＋旧十核心；
3. 相同枚举＋八来源失败的部分状态 nogood 与旧十核心；
4. 相同枚举＋十八核心逐候选重检；
5. 同十八核心＋成组选项特征编译。

所有组都有相同独立动作下界，以及共同来源 ready 后缀缓存；缓存命中仍必须逐动作和历史监测核验，错误缓存当作未命中。不给任何组目标任务答案，不增大目标缓存。完整部分 nogood 包络的条件表与十八核心等价，另逐状态核验，不将其伪装成较弱对照。

第五组必须考虑所有备选项能引入的新原子和新冲突，不能沿用“删除不会引入特征”的旧假设。审计每个授权替换上的编译特征与原 features 相等、编译拒绝与原 bank.evidence 相等。相同信息导致等价时，不宣称独特表达能力。

三次计时，循环/反转组顺序。每组实际新建域、下界、共同缓存、所需库的原认证、解码任务、生成全部候选和检索均计费；原完整求解调用和缓存验证单列。来源获取/学习费用未重新计入，只比较已有来源知识后的查询阶段。原全规划器无剪枝穷举至首个 ready 的最优性审计及 ready 后缀审计在计时之外。

**停止与论文边界。**补全正确性、最优性、目的许可、来源增量和强对照归因后即停止这一轮扩展。即使有速度收益，也不认定已首创替换/最小修订；已有 Automata-based Optimal Planning with Relaxed Specifications 等研究用户许可的替换、删除及分组。本轮最多支持有限符号模型中的许可保持任务修订模块，不证明自主理解用户意图、开放世界或物理效果。
