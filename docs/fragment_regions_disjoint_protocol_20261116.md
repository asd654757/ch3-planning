# 开发签名剔除后的补充复验

本说明在补充计时和签名交集统计之前写入；原完整组合验证已显示前四轮结果，因此这是透明的审计追加，不冒充全程未见结果的预注册。原验证保持不变。

可能的重叠来源是：此前真实模型案例含四/五条静态条款，而原 7,532 个有限组合主体只含至多三条。完整新网格可能包含少量与旧案例在松弛任务与状态上等价的输入，单凭条款数量不能保证完全分离。

预先固定剔除依据：取两个旧 context_memory 开发/验证 cases.json，以及旧 revision_fragments 的全部 cases.json；对各输入计算 `(eligible_atoms(snapshot), current_state)` 签名。它去除案例名、条款 ID、任务版本和观测 ID，并保守忽略历史顺序。删除新网格中与这些已见签名相同的全部输入，不读取新结果标签决定取舍。校准流是旧组合的子集，已包含在上述来源。

不改学习库、专家核心、认证方法、动作预算、特征闭包和匹配器。保留原网格及其结果，报告交集具体案例、剔除后的唯一输入数和调用差异。补充五轮只复验主对照 expert 与 learned，使用同一原始网格的剩余全部输入及已归档原求解器结论检查正确性。原始四组五轮结果用于总体和消融展示，不能用补充结果覆盖原记录。

补充每轮随机种子 9073＋轮次，共同打乱输入，方法顺序交替，单进程串行。保存每轮墙钟、CPU、调用数和结论摘要。仅计时重复次数改变，不增加独立输入或机器人试验数。

包含构建费用的总算法计算成本定义为：expert 的旧专家构建时间＋本次专家证书重新认证＋一个查询批次；learned 的旧完整训练准备时间＋冻结 256 个校准输入的解析时间＋本次学习库证书重新认证＋一个查询批次。校准输入解析另外计入，避免冻结训练文件的读取费用被遗漏。共同测试数据集的生成、载入、输出归档、分析，以及模型/机器人延迟不在算法计时中；不把本实验称为端到端机器人加速。

只有剩余全部输入三态一致、每轮相同结论，并且主对照的运行成本有下降，才报告本限定工作负载的优势。若一次性构建费用抵消收益，明确记录。不能利用重复五轮来重复摊薄构建成本。
