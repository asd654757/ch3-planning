# 失败片段用于历史保持的最小任务修订：先导协议

本协议在本轮实验前写入。目的不是再声称 nogood 或最小修订首创，而是检验现有失败知识能否有效指导“删去哪些允许放弃的要求，才可恢复执行”。仅生成候选，不接受修订、不下发动作。

## 固定问题

使用已冻结执行轨迹中全部非 ready 判断，不筛选成功案例；保留每个判断的原状态、完整历史、任务版本和每项 since。H=8。禁止删除 forbid、before，以及按 ID 排序的首个 at 要求；其余要求可删除，每项代价 1。结构不合法的删除组合（留下悬空 before）不进入候选集。按总代价、删除 ID 元组排序，返回第一个有共同可执行后缀的候选；未知历史仍须原模型的所有分支共同满足，need_observation 不算修订成功。

候选集合相同，至多 2^m，未引入语言模型或改变规划器。原非 ready 判定对各组均作为共同输入，免收一次重复查询。每个任务内均可缓存自己实际求解过的候选；任务间不积累目标集答案。

## 方法与强对照

1. `enumerate`：按相同顺序逐个检验候选，含共同独立动作下界。
2. `online_core`：已有隐式击中集思路；失败后在可删除要求层面做贪心缩核，排除保留该核心的其他候选。所有缩核查询计费。
3. `transfer_union`：在 2 上添加已有完整认证库，从命中片段涉及的原要求并集中至少删一项。多个来源合并只提供较弱必要条件。
4. `transfer_support`：在 2 上添加精确来源公式：要破坏片段，必须令至少一个片段原子失去**全部**保留要求的支持。对每个片段 K，约束为 `OR_a_in_K AND_requirement_supporting_a delete(requirement)`。硬要求不能删除。
5. `transfer_recheck`：在 2 上对每个候选重新提取必要特征、查询同一认证库。它拥有与 4 相同信息及逻辑覆盖，是用于揭示“只是预编译”的强对照。
6. `transfer_support_fixed`：运行 4 的同一算法，但只用旧十核心，隔离新八个失败片段的增量。

所有组共用相同独立动作下界、原完整规划器、候选排序、缩核程序、历史监测及 ready 后缀核验；4 与 5 预期等价，若成立不能宣称新表达能力。来源库使用冻结的 18 核心，载入需原认证器重算；载入时间单列，不能隐去，已有来源学习成本不重新摊薄。前两组不加载用不到的来源库，不承担其费用；第六组只加载旧十核心。

## 判据和限制

先导只用一个固定工作负载，计时 3 次并循环组顺序。审计在计时外使用无剪枝原规划器逐个检验，核对最优代价、同序修订及每个后缀；另核对全部保留项及 since 完全不变。记录不可修订比例、原规划器调用（包括缩核）、候选数、拒绝来源、各组准备和总时间。若 4 与 5 无实质差异，应把来源公式视为编译方式，不能再包装成独立算法创新。

该方向邻近已有最小规约修订、核心引导 MCS、MaxHS/隐式击中集。即使性能改善，也仅能首先支持“复用既有失败知识指导最小可执行修订”的候选贡献；独立新颖性、自然语言意图保真与物理效果均待进一步核查。不把删除要求称为完成原任务，不以建议可行率代替原任务成功率。
