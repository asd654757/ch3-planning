# 执行历史约束下的任务语义修订：实现与研究验收

**结论：方法原型、真实模型对照、物理证据桥接和错误审计已完成；当前实验尚未支持“可投稿的方法贡献已经成立”。** 保留这一实现作为研究基础，不把它包装成已经优于强重规划的方法。

## 1. 本轮新增了什么

原项目已有完整任务指令解析、规则解析、符号搜索和任务切换实验。此次新增的代码位于 `ch3/revision/`，没有替换原有执行链路。

| 模块 | 实际能力 |
| --- | --- |
| `history.py` | 带生效时间的任务条款、只读事件记录、快照摘要、原子编辑、完整重译和修改范围对照、联合历史/后缀搜索 |
| `evaluation.py` | 修订影响向依赖条款传播；独立金标准契约与后缀评分；历史/终局消融 |
| `diagnosis.py` | 可复核的有界冲突核、最小旧事件证据查询集合、明确标为改变任务的修复选项 |
| `session.py` | 冲突修订暂停旧任务；后续指令修改待解决的新意图；可执行版本才提交 |
| `model.py` | 同一模型的增量编辑、完整重译、完整重译加修改范围三个接口 |

大模型承担自然语言到条款编辑的解释；生效时间赋值、历史检查、依赖传播、动作搜索、冲突核和证据查询都由程序计算。引用原文只验证来源，不能保证大模型正确理解了指令。

## 2. 方法定义与保证边界

任务版本为条款集合，每项带稳定标识和生效游标。支持最终位置 `at`、最终空手 `empty`、生效后禁止操作 `forbid`、生效后发生放置 `visit`，以及两个 visit 首次合格事件的 `before` 关系。

未改条款保留原游标；新增或内容改变的条款从当前记录之后生效。新增顺序可以引用旧 visit，因此会受到真实既往事件约束。要“重新执行同一次必经放置”，必须创建新 visit 身份并更新引用，不能把旧事件清除。修改某个 visit 时，即使顺序条款文字未变，它也进入依赖影响集合。

令 H 为证据允许的历史解释集合，L 为动作上限，V(h,π) 表示从当前状态执行后缀 π 能满足修订任务及历史约束：

- **ready**：存在长度不超过 L 的同一后缀 π，对所有 h∈H 都有 V(h,π)。
- **conflict**：对所有 h∈H，都不存在长度不超过 L 的可行后缀。
- **need_observation**：其余情况，包含只有部分历史解释可完成、或各解释需要不同后缀。

BFS 根据当前状态及各历史解释中 visit 的完成情况合并搜索节点。已发生的逆序和禁令违反先行剪枝；在没有历史违反的节点中，未来只需要知道各 visit 是否已经发生，而不需要保留全部预测轨迹的具体时间。因此在本有限动作模型中不会因这一合并丢掉不同的有效未来。BFS 返回有界最短共同后缀。50 组随机小实例用无节点合并的穷举搜索核对这一剪枝。

这是模型内的保证：两块、三个位置、单手、区域容量一、确定性 pick/place，默认上限八个动作。未确认事件最多六项，枚举包含/不包含的证据解释。枚举不利用物理状态转移进一步过滤历史世界，是一种保守证据抽象。输入当前状态被假定为新鲜且有支持的观测；程序不会从动作回执推断它。`conflict` 不等于在开放物理世界中无界不可行。

冲突核是在依赖闭合删除规则下的**删除极小集**，不宣称条款数全局最少。历史证据查询采用枚举，求能让所有回答分支不再需要补证据的最少事件集合；它不是最优自适应问答策略。对过去事件，应检查当时存档证据；现在拍一张图通常不能证明过去的顺序。本实现计算查询对象，不实现档案检索或保证旧事件可被查清。无法查清时只能保留暂停或由用户明确改变时间范围。

修复选项包括删去相关要求或明确重启 visit 范围。它们改变原任务，必须经后续明确修订，不能计为完成原来的冲突请求，也不会自动提交。

## 3. 同信息真实模型对照

使用既有 `deepseek-v4.1-flash` 接口，temperature=0.1、seed=0、每次最多 4096 输出 token、无重试、两路并发。每案例每方法一次调用；全部方法共享初始已确认契约、更新指令、当前状态、历史、能力、时间规则和同一后缀检查器。金标准不进入提示词。

这里的强基线是**完整重译＋统一符号后缀搜索**，不是让大模型自由生成动作的较弱基线。完整重译加修改范围的对照还能用程序保留未声明改变的条款，用于区分输出格式和保留机制的效果。

开发集十二例，验证集二十四例，均为作者构造。验证集改变对象角色、目标位置和表述，仍来自同样十二个机制族，因此不视为新任务域上的独立泛化证据。所有案例在调用前冻结，不根据结果补选案例。

| 验证集（24 例/方法） | 规范化契约匹配 | 状态判定正确 | 可完成例有效后缀 | 冲突识别 | 必要历史证据查询 | token 总量 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 增量编辑 | 24/24 | 24/24 | 14/14 | 8/8 | 2/2 | 35,859 |
| 完整重译 | 24/24 | 24/24 | 14/14 | 8/8 | 2/2 | 32,173 |
| 完整重译＋修改范围 | 24/24 | 24/24 | 14/14 | 8/8 | 2/2 | 34,085 |

规范化契约匹配忽略标识重命名，但保留 visit/forbid 生效时间和顺序引用含义；它是条款多重集匹配，并非一般逻辑等价判定。冲突和补证据没有混入任务完成分母。三种方法均无接口失败、无对金标准无效的 ready 后缀。修正依赖影响口径后，三种方法均保留 56/56 项未受影响条款。

**增量编辑没有准确率优势，token 比完整重译多 11.46%。** 不能以结构化编辑更短为由宣称调用成本更低。延迟受服务和并发影响，此样本不支持稳定速度结论。

开发集的增量编辑和完整重译均为 12/12，第三种对照为 11/12。该例保留了旧条款又添加新条款，规范化契约不匹配，但历史状态判断仍正确；不是观察到不安全动作。开发集观测编号含机制族名，属于额外语境，因此仅记录为开发诊断；验证集在调用前已改成无语义的哈希编号。两轮共 108 次模型调用、152,892 token，没有删除不利结果。

## 4. 机制消融：说明需要历史，不能证明整个新方法独有优势

此消融向检查器提供人工金标准契约，隔离历史机制，不包含自然语言理解误差。

| 检查方式 | 24 例状态正确数 |
| --- | ---: |
| 完整历史与条款 | 24/24 |
| 忽略已发生事件，保留逻辑时钟 | 18/24 |
| 只检查最终位置和空手 | 16/24 |

错误集中在已经逆序、新顺序引用旧事件、证据未确认，以及持有对象时新增禁令等问题。它说明终局位置不足以表达所选问题。由于强完整重译同样接入了历史检查器并达到 24/24，这不能当作增量算法优于强重规划的证据。未运行新的规则语言解析对照，因此也没有“优于所有简单规则”的结论。

诊断案例中，逆序冲突核为对应的两个 visit 加顺序条款；容量冲突核为两个同区域最终位置要求；未确认首次事件只需要查旧事件 2，不会把其余无关未知事件全部加入问题。

## 5. 真实 MuJoCo 证据桥接

三次物理执行前缀使用 seed 1110/1111/1112。先执行抓取和放置，用 RGB 共动确认抓取、释放退离与目标稳定性确认释放，再用独立初始区域 RGB 参照判断到达。控制器完成回执本身不产生确认的放置事件。

已发生的“蓝块进入绿色区”被写入只读记录。随后脚本提出“原有回桌面必经事件须早于这次进绿色区”的修订：系统判冲突并暂停。脚本后续明确取消顺序及回桌面要求、增加从现在起的禁令，系统接受已经完成的绿色必经要求，保留原记录且无需额外动作。

三次均通过历史保持、暂停与后续修订检查，独立终局几何评分亦为 3/3。修订决策期间控制步数均为零，完整前缀及证据采集分别为 311、310、311 步，每例仅一次 episode reset。**这是三个物理前缀及其脚本修订集成检查，不是 LLM 完整机器人任务成功率或方法间物理性能对照。** 后缀搜索预测不会写进实际历史。

记录：`data/collections/history_revision_robot_bridge_20261112_v2/`。首次桥接运行在 seed 1110 执行后因冲突选项对象的 JSON 归档失败而退出，保留在 v1 目录并记为一次未评分失败；不能把它算成额外成功。开发基准首次启动的路径归档错误发生在任何模型调用前，也单独留档。修正均针对归档器，重新运行使用新目录。

## 6. 与相关工作的关系及论文判定

自然语言在运行时更新机器人规划模型早已有研究，因此“运行中听懂新指令并更新计划”本身不能认领为新贡献。参见 [Cantrell 等，HRI 2012](https://hrilab.tufts.edu/publications/cantrelletal12hri.pdf)。

将形式子要求映射回原文并交互增删修改也已有框架，不能把条款编辑或来源引用本身作为独有创新。参见 [nl2spec，2023](https://arxiv.org/abs/2303.04864)。

用执行轨迹帮助用户验证形式语义、选择区分性问题同样存在强相关工作。参见 [ARTEMIS，ICSE 2026](https://cs.stanford.edu/~trippel/pubs/mendoza_ICSE26.pdf)。本轮实现的是已发生事件的不确定证据查询，不等于 ARTEMIS 的候选规格区分轨迹；这一差异尚未构成经过对照验证的新算法主张。

本轮可以准确描述的研究对象是：**带生效边界的条款修订如何与不可改写、部分确认的历史共同决定剩余任务及澄清对象。** 但原型中使用的有界搜索、依赖闭包、极小冲突核及有限证据枚举都是常规技术；把它们组合起来并不能自动满足方法新颖性。

当前未通过“小论文方法贡献”验收，原因是：强对照持平；无成本改善；域很小且案例作者构造；没有证明语义解释完整性；没有与在线时序规格修订/监控和标准诊断算法进行直接方法比较。3 个桥接前缀不足以填补这些缺口。

后续若继续追求投稿，应先选择一个强基线不能等价完成的明确算法问题，给出形式差异和可证性质，再做独立案例族实验；例如研究不可恢复历史证据条件下、保持未改意图的可执行修订及必要澄清，但必须进一步对照相关规格修订和诊断方法。不会通过移除强基线历史输入、放宽其验收规则、重跑到出现优势，或迁移机器人平台来代替这个缺口。
