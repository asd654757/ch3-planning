# 主题核对：大模型规划与反馈修复接入pilot

## 本次直接服务的主题

大模型生成机器人任务计划；确定性校验拒绝错误候选；具体诊断反馈触发真实模型修正；实际执行通过校验的模型动作，而不是悄悄替换为固定参考计划。使用自然执行，无故障注入。先运行3个seed×两种设置，不能作为正式性能结论。

## 设置与公平性

- MODEL_NO_PLAN_REPAIR：一次初始模型生成，校验拒绝则停止；执行中保留相同的两轮目标重新观察能力。
- MODEL_DIAGNOSTIC_REPAIR：共用同一首轮候选，拒绝时最多额外一次模型修正；实际释放证据支持蓝物体完成后，重新校验原模型后缀，从当前支持状态修正被拒绝的后缀。

同一seed首轮输入图像SHA256和请求完全一致才允许候选复用；实际调用与复用标记分开记录，按seed交替运行顺序。初始视觉、执行控制、观察预算与评分相同。无恢复设置预算较少，故这里只是接线与有无恢复对照，不是等预算反馈消融。若自然候选都通过且后缀一致，应报告修复未触发，不注入候选错误制造差异。

## 数据来源与能力边界

图像实际输入VLM，初始状态仍来自受控已知对象在桌面的fixture，而非VLM独立估计。中间状态来自RGB支持的蓝物体释放及黄物体未动的fixture，不用模拟器物体真值授权。模型输出的pick/place记录经本地严格解析、Validator、Goal Checker及后端序列范围检查才编译执行。

现有执行器支持蓝先黄后的两个相邻pick/place对；不支持任意交错、额外动作或第三目标，超范围计划显式拒绝，不自动改写。此限制使接线pilot规划较简单，不能宣称非结构化任务泛化。

**当前接入不等于完整执行失败恢复**：持物、释放证据未知或控制异常仍安全停止，不把未知当空手，不用原fixture伪造重规划状态。本轮真实调用可以验证初始规划与计划拒绝修复；执行失败后的通用观测状态恢复仍需后续接入，不能声称已经实现完整ROUTED。自然执行若没有计划错误，则修正调用为0，是合法结果。
