# 多物体 RGB 定位与固定控制器抓取接口验证（2026-10-01）

## 本次实现

- `FixedPickPlaceController` 接收后端中立 `SkillRequest`，使用视觉估计目标坐标与机器人自身末端位置反馈执行固定路径；不读取物体真实坐标、奖励或原环境的单物体目标。
- 仅支持右臂 pick/place；包含绑定来源、观测标识、坐标系、工作空间与步数预算检查。这些检查不等于碰撞安全保证。
- `multiobject_pickplace_smoke.py` 从 RGB 中以已知蓝/绿色阈值提取目标像素，结合固定相机标定和显式高度假设构造坐标。脚本目前只执行 pick，未执行 place。
- 控制器 `completed` 只表示路径阶段完成，不表示抓取成功；物体抬升信息置于 `evaluation_only`，不能作为在线执行分支条件。

## 实际结果

产物：`data/collections/multiobject_rgb_pick_smoke_20261001_v1/` 与 `v2/`。

v1 为首次抓取验证；v2 修正控制器步数预算边界并补充评估记录后，用相同 seed=0 重复验证。两次不是两个独立统计样本。

## 科学边界

1. 这是已知颜色、固定光照、固定相机、已知物体高度的受限接口测试，不是通用独立检测器，更不是开放世界实验。
2. 没有使用自然语言指令解析、VLM 决策或 ROUTED，所以该结果不能证明规划修复模块优于其他方法。
3. 没有接入 ACT/AD-Flow。后端契约允许今后替换技能策略，但当前实际控制方式是固定路径控制器。
4. 评估器使用物体真值仅计算抬升与位移，不提供在线目标绑定，也不触发放置。
5. 全掩膜中位数定位遇到多个同色物体、遮挡、颜色相似部件时会失效，当前不支持这类泛化主张。

## 下一步顺序

1. 实现保守的在线视觉持物确认：执行前后目标区域、末端相对位置及短时跟随证据；证据不足则标记 unknown，不能用真值补全。
2. 在同一场景中重新获取图像，刷新绑定；持物确认后再执行 place，并用独立评估评分。
3. 接入自然语言目标解析及现有 Validator/恢复模块，确保实际执行反馈而非预测前缀终态驱动恢复。
4. 小规模检查成功/失败抓取与目标变化后，再冻结连续场景对照；不要直接扩大为正式大规模实验。
