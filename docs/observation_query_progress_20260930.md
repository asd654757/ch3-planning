# 缺失项驱动补充观测诊断

## 实现

在初次图像定位和语义解析后，程序根据已返回的关系计算缺失项，例如 `location:blue_cylinder` 和 `hand_state:right`。补充观测调用只能回答程序列出的请求，只能使用已有局部对象 ID，不能重写定位结果、任务目标或执行动作。

如果模型把请求放入 `unresolved`，即使同时生成了看似合理的关系，程序也不接受这些关系。这样避免“模型一边说证据不足，一边用猜测填状态”的隐式放行。

## 小规模结果

`staged_grounding_multiview_20260930_v2.jsonl` 使用同一多视角、同一场景和 seed=0，完成 3 次模型调用：定位、初次语义解析、缺失项补问。

- 首次解析目标仍为 `on(red_cylinder, green_square)`；
- 程序列出三个缺失项：两个对象位置和右手状态；
- 补问模型返回了部分关系，但把三个请求都标记为 `unresolved`；
- 系统保持拒绝，未进入规划，未执行动作。

这证明了“缺失项驱动补问”和安全拒绝路径已经运行，但不证明视觉状态恢复成功率提升。当前瓶颈是模型对多视角中的对象位置和手状态证据判断仍不稳定。

## 后续边界

下一步应把补问进一步拆成单请求调用，并要求每个答案绑定到对应请求；同时为 hand-state 设计专门近景输入。只有单请求的 `resolved` 与关系一致时才合并。仍不得使用 evaluator truth 作为在线输入。
