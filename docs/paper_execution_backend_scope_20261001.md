# 小论文执行后端与大论文接口边界

## 冻结研究范围

小论文核心为语言—视觉输入下的任务级规划校验与执行状态感知恢复，不训练 ACT，不接入 AD-Flow。执行侧采用固定仿真技能控制器。大论文后续可以适配已有 AD-Flow，但须独立验证，不将当前结果外推为 AD-Flow 集成效果。

现有 `metaworld_executor.py` 实际使用专家策略与程序化阶段控制；历史 `adflow_grasp` / `adflow_place` 是注册表路由名称，并非权重加载证据。保留旧配置和原始实验记录，不改写数据。

## 新增接口

`ch3/execution/skill_contract.py` 提供后端中立的请求构建：

- `skill` 与实际 `backend` 分离；
- 对象和目标必须显式绑定，禁止回落到默认单物体；
- 绑定声明三维位置、坐标系、观测身份和来源；
- 默认拒绝 simulator_truth 来源、旧观测绑定、错误坐标系、非有限坐标；
- place/push 必须具有目标绑定，包括 table 这样的命名区域；
- 不进行图像框到三维坐标的转换，也不自动验证感知正确性。

这是新增接口与准入检查，尚未接入现有执行器；旧 executor 不会因为新增文件就获得这些保护。它也不替代 Validator、Goal Checker、碰撞与可达性检查。观测身份匹配只是最低限度的新鲜度检查，不是跨帧跟踪或动态安全保证。

## 实验协议

后续所有恢复策略共用同一感知前端与固定执行后端，固定任务、seed、反馈和预算。分开报告任务理解、计划就绪、技能执行、受扰恢复和最终任务成功，最终评估不能仅依赖模型自报状态。

非结构化输入不意味着去掉机器人本体反馈或相机标定。允许关节、末端和夹爪测量；禁止将闭合夹爪直接解释成持有指定对象。物体 pose/身份真值与评估标签不得流入在线目标选择和绑定。

## 下一阶段实施顺序（未完成）

1. 固定相机标定与目标位置转换协议；可以采用桌面平面假设，必须报告高度/遮挡限制。候选检测是支持模块，不作为论文核心创新。
2. 用独立评估核验目标身份和持物判断；此前 `holding(right, red_cylinder)` 只是模型答案，不是感知正确证据。
3. 将真实绑定传入新契约，再实现多物体参数化 pick/place 控制器；不可复用旧单物体别名行为。
4. 同一持续场景上做小规模实际执行，再比较无恢复、直接反馈重规划与受约束恢复。通过后才冻结正式集。
