# 自然语言目标与持续场景剩余计划：首次接口验证

## 实现与实际结果

新增 `ch3/vlm/persistent_scene_bridge.py`。允许输入只包括指令、当前图像、已知颜色适配器提供的两个候选说明、右臂能力，以及在线持物证据。接口不接受仿真物体状态。

v3 指令：“把蓝色方块放到绿色区域。”

实际路径：

1. VLM 根据指令/图像解析蓝色候选到绿色区域的目标；候选范围预先受限，不能声称自动发现所有物体。
2. 程序执行固定初始 pick（初始完整计划不是模型生成）。
3. 首轮观测人为黑屏，额外一轮重新采样后持物证据通过。
4. VLM 根据在线 holding 事实与新图像生成剩余 place；没有重新生成或执行旧 pick。
5. Validator 校验模型输出及模拟后的目标；仅一条合法 place 才能编译执行。失败时拒绝，不用固定后缀替代模型输出。
6. 单次持续场景中完成放置，独立评估 `task_success=true`。

模型调用 2 次（目标解析与剩余计划各 1 次）；场景初始化 1 次。日志保留两次调用的原始响应、prompt、token、延迟和图像哈希。

产物：`data/collections/multiobject_language_remaining_20261001_v3/`。

## 失败记录和数据口径

- v1 指令另含“不要移动其他物体”，目标接口拒绝，没有执行；不得把这种行为写为约束已被支持。
- v2 修改严格输出字段后模型复述 JSON Schema，输出截断，解析失败，没有执行；保留完整可获得原响应。
- v3 将提示改为紧凑输出字段说明而非 JSON Schema，实际两次响应均可解析，任务完成。
- v3 summary 的 scope 字符串来自运行时旧文案，误写 no language planner；该产物中的 language_goal、model_calls=2、原始调用与 plan_source 明确记录真实执行。脚本已修正文案，不覆盖旧实验记录。

三轮是版本诊断，不是冻结协议下的三次随机重复，不应汇总为正式成功率。

## 重要限制

这是受限语言目标解析和观测状态条件下的剩余计划生成，并非完整自然语言视觉恢复 benchmark。没有使用现有 R1/R2 或 ROUTED 策略，不能归因于这些模块。初始 pick 仍是脚本生成，目的区域桌面位置与高度属于场景假设。

禁止动作、时序等额外要求必须报告 unsupported_constraints 并拒绝执行。该机制依赖模型正确报告限制，尚没有独立完备的自然语言约束检测器，所以不能保证所有复杂指令都会被正确拒绝。

目前只允许蓝色方块到绿色区域的一次 transport，图像定位仍是颜色启发式。没有开放世界目标绑定、通用视觉定位、最终目标的在线视觉判定或接触力证据。

## 下一步
