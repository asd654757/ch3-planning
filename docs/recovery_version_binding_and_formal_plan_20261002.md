# 版本绑定、进度账本与正式实验准备（2026-10-02）

## 本轮实现，而非已取得的性能结论

- `ch3/execution/recovery_context.py`：任务版本、观测版本、指令/目标摘要、图像/事实/来源摘要绑定到本地请求票据；新任务或新观测使旧响应失效。票据不可重复消费。模型不需要复述版本字段，避免加重结构化输出负担。
- 执行历史是只追加的事件序列，当前事实只从声明来源的观测写入。执行命令或历史成功不自动产生当前目标事实；效果丢失后目标重新列入剩余目标。
- 前一技能结果、下一技能前置条件、意图是否匹配分别输入路由。未知时有界再观测/停止；简单、状态未变且后端允许时一次固定重试；目标/前置条件变化时从当前状态重规划。
- **路由函数目前是经过单元测试的决策组件，不是整个持续场景运行器已经接入了完整 ROUTED。** `retry_authorized` 必须另由执行后端的恢复门控提供，不能由模型自行宣称。
- `task_switch_recovery.py` 已真实接入调用前后版本核对。`task_switch_planning_smoke.py` v2 记录初始任务版本1、诊断历史 pick、外部任务更新到版本2，然后请求新剩余计划。
- 这是单线程上下文；异步并发系统需锁或原子检查。物理调度前还要再次核对当前版本、目标绑定和执行前置条件，不能只凭规划时的检查。

## 本轮数据 lineage

`data/collections/task_switch_version_binding_20261002_v1`：单次真实模型规划调用，自动创建任务版本1的诊断上下文；显式结构化状态，复用旧 RGB，没有新物理执行。

`..._v2`：同样是单次真实模型规划调用，但运行器显式创建原任务和诊断执行事件，再切换到版本2。历史事件来源标为 fixture，不伪称本轮机器人真的执行了 pick。

两份均是机制诊断，不并入旧正式成功率，不作为在线恢复性能样本。原始响应、token、图像 SHA、版本绑定和校验结果均保留。手写释放/运输对照同样能通过，故不能证明大模型在准确符号状态下优于规则。

回归测试：本轮相关15个测试文件，119 passed。新增覆盖旧任务响应、新观测失效、相同图像但新观测、重复消费、目标效果丢失、unknown清空事实、重复历史事件、不同路由分支。

## 最短正式实验路径

不要继续增加相同的简单固定重试样本。优先完成同一持续场景内真正改变剩余序列的实例：

1. 蓝色已经持有，外部指令切换为黄色运输。
2. 从 RGB 候选与校准得到黄色定位；缺失、多个候选或越界必须拒绝。
3. 蓝色返回桌面的目的地需独立、明确绑定（优先可见返回区域）。不能把符号 `table` 偷换成仿真物体真值坐标。
4. 释放之后取得新的 RGB/机械臂反馈，确认可支持的释放/手状态，才能抓黄色；控制器完成不等于释放已成功。观测不足则停止，不能默认空手。
5. 后续每阶段保持同一 episode，不 reset，不重放历史 pick；最终真值评分与在线事实来源分开。

上述1–5当前尚未全部实现，因此暂不启动正式任务切换执行 benchmark。

### 待 pilot 的比较设置（非“几臂”）

- `FIXED_RECOVERY`：共享语言解析、初始计划和观测接口，故障后采用受限规则恢复/一次后端允许的重试。必须给规则基线相同信息；不能故意不给新目标。
- `CURRENT_STATE_REPLAN`：相同新任务与新证据，直接规划剩余任务，相同技能后端与安全门控。
- `VERIFIED_ADAPTIVE_RECOVERY`：当前证据与版本检查、有限观测、状态未变时固定重试、需要改序列时当前状态规划、确定性校验及目标检查。

若最后只是额外一次模型调用而没有实际路由，不称完整自适应方法。所有设置共享安全执行合同，Goal Checker 消融也不能取消基础动作安全限制。

### 建议正式规模（待 pilot 后冻结，未生成/未运行）

10个场景 seed × 5类条件 = 50个条件实例，每实例3种设置，共150次任务运行：

1. 无扰动运输；
2. 受控早期 pre-contact 超时、目标未变；
3. 持蓝色后外部目标切换到黄色；
4. 临时反馈缺失、限额内可恢复；
5. 持续反馈缺失、预期安全停止。

seed只改变当前场景允许的位置，不能称作10类任务或跨场景泛化。目标切换是外部指令变化，早期超时是受控失败，不混称自然模型/机器人错误。临时和持续缺失是可观测性条件。

先取3个seed检查协议和后端可执行性，不按是否有优势筛选条件。正式 manifest 在 pilot 和代码冻结后生成，包含图像/候选来源、指令、条件注入、方法预算、模型与代码版本；方法执行顺序轮换。不得边看结果边改 prompt 并合并数据。

### 正式分析

- 全部启动实例计入分母，前端拒绝/格式错误/未知停止不删除。
- 分开报告：最终实际成功、可恢复故障恢复率、持续缺失下误执行与安全停止、调用/token/步数、当前事实与独立评分不一致。
- 目标切换子集判断计划是否真正改变；固定重试成功不算模型规划贡献。
- 所有设置共享可用证据及单次失败后的预算。按场景seed配对；重复条件相关，用cluster置信区间，不把150次运行当150个独立任务。
- 结果不要求自适应方法一定优于规则；若同分，报告成本和适用边界。当前闭世界执行合同与有限颜色候选不等于开放世界。
