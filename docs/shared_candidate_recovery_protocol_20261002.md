# 共享首轮候选的错误反馈机制pilot

## 目的

消除v4两设置首轮实际输出不相同的混杂。只用原15案例清单，不增加难度、不选择旧胜利或失败案例。结果是符号机制检验，不是视觉或物理benchmark。

## 预固定协议

每案例只生成一次共同首轮候选。首次通过则两设置共用通过候选，无额外调用；首次无响应则保留失败且不伪造候选。首次有响应但被拒绝，则将完全相同的previous_candidate传给两个分支。两分支均共享当前状态、历史、掉落事件、目标、固定右臂适配器、基础校验和动作约束，分别追加一次调用：

- NO_ERROR_FEEDBACK：有同一候选，但无具体校验反馈。
- ERROR_FEEDBACK：有同一候选，加实际校验错误。

因此比较的是具体诊断反馈，而非“一个知道候选、另一个不知道”。每实例分支顺序按清单奇偶交替，降低调用顺序偏差；不声称完全排除服务端随机性。模型、温度、seed保持原值，候选SHA256和完整请求记录。同种子不保证独立随机重采样。

每方法逻辑预算最多2次（共同首轮＋一次修正）；物理实际API总数是每案例1或3，需避免两次计算共同首轮。15案例最多45次调用。

## 分母与归因

所有15案例保留，另外报告实际共同失败候选子集。没有失败候选就报告修正未触发；不得注入错误混入自然输出结果或加任务追求区分度。候选合法、预测目标、动作约束都满足才接受。物理成功字段为null。

静态机制pilot使用同一当前状态，不能声称解决执行中状态变化或异步请求过期。自然候选冻结只服务机制消融，不能写为在线端到端实验。小样本角色排列不当作独立自然任务分布。

代码：shared_candidate_recovery_pilot.py；分析：analyze_shared_candidate_recovery.py。新增测试核对共用候选、仅feedback请求字段不同、共同成功无冗余调用及缺失响应保留。
