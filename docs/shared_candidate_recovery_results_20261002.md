# 共享候选恢复 pilot：结果、贡献边界与后续门槛

## 数据与协议

- 原始数据：`data/collections/shared_candidate_recovery_pilot_20261002_142344.jsonl`。
- 汇总：同名 `_summary.json`；分析脚本 `scripts/analyze_shared_candidate_recovery.py`。
- 协议：`docs/shared_candidate_recovery_protocol_20261002.md`。
- 原清单全部15案例保留；完整性审计通过，无缺失或重复案例，无首轮响应缺失。
- 每案例共享同一首轮候选；若被拒绝，两设置各追加一次调用，请求差别仅为具体校验反馈。分支调用顺序交替。
- 这是符号状态下的机制pilot，不是实际物理执行、视觉闭环或完整ROUTED实验。

配对结果：错误反馈胜1例、负0例、同结果14例。差异为1个案例，不足以支持稳定优势或统计显著性；而且15案例只是3类模板的对象角色排列，并非15个独立自然场景。

## 失败诊断

6个首轮拒绝均为 `OBJECT_NOT_HELD`：模型依据历史抓取直接生成place，忽略当前掉落后的空手状态。未出现schema/arm接口错误。

- partial_01、partial_02、partial_04、constrained_02：两设置均修正成功。
- constrained_04：无反馈只完成另一个待办物体，遗漏掉落物体；有反馈补全全部剩余目标。这是唯一配对收益。
- constrained_00：两设置都只完成另一个待办物体，遗漏掉落物体。动作结构合法，但目标未完成，均被Goal Checker拒绝。

日志在结构合法但目标失败时记录 `error_code: "None"`、空message，且 `goal_satisfied: false`。分析中应归类为目标未满足，而不是“无错误/成功”。这也指出未来反馈协议应显式区分动作错误与剩余目标遗漏；若修改，应使用新协议版本，不能覆盖本轮数据。

## 可写与不可写

可写：在相同首轮候选、当前状态和修正预算下，具体校验反馈在一个受控案例中帮助补全剩余任务；Validator与Goal Checker联合阻止未完成目标的候选进入执行。

不可写：反馈稳定提升整体成功率；大模型优于准确符号搜索；物理恢复达到93.3%；本轮是视觉反馈或完整主方法的正式验证。

上一轮v4的11/15与15/15来自分别生成的首轮候选，只作为开发观察，不能用来替代本轮严格配对结果。所有版本独立保留，不混合分母。

## 后续顺序：不为制造差异扩任务

1. 先完成同一持续多物体场景的参考控制器可执行性检验：新增第三目标区域前核对可视性、可达性与碰撞；固定参考计划连续搬运多个物体，验证已完成且禁止移动的物体不被扰动。单episode，不用reset伪造恢复。
2. 控制器可执行后做小规模掉落恢复：记录历史、实际当前观测、剩余目标，区分规划失败、状态估计失败与控制失败。观测来源如是模拟器真值必须明确标注，不伪装为视觉估计。
3. 独立终态评分与在线决策信息分离；只有实际落地执行才报告物理恢复成功率。保留固定搜索参考，检验性能提升是否只是后端重复尝试的收益。
4. 在上述门槛通过后冻结新正式协议；比较相同任务、物理初始条件、扰动和最大调用预算。继续采用共同候选机制检验来解释反馈贡献，不用小pilot的胜利案例选择正式任务。
