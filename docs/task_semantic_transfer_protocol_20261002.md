# 新措辞任务语义对照 v1：冻结协议

## 测试集与冻结

`data/scenarios/task_semantic_transfer_v1.jsonl`24条：受控语法12、自由改写8、应拒绝4。均不同于先前12条开发指令的全文，覆盖取消、持物指代、目标对象切换、禁止动作与最终放置顺序。作者构造且知道规则语法；**不是独立第三方集，不是随机自然任务分布**。规则代码先于此集写入git，冻结后不根据结果修改任何方法或标注。本轮为新措辞pilot，尚不称formal。

目标注释由开发者创建，先检查符号可达性。现有两cube/green/table与持blue状态不变；换持物、空手、视觉歧义场景均未覆盖。模态输入为语言与共享已落地符号候选/状态，未做新的图像解析。无物理执行。

## 比较设置

- 规则语义解析＋确定性搜索：受控语言baseline，未识别分句整任务澄清。
- 模型语义解析＋同一确定性搜索：测试多样语言接口，不混入模型规划错误。
- 同一模型语义解析＋模型剩余规划：测试完整语义—计划链。
- 人工正确语义＋搜索：仅oracle上界，不是自然语言方法。

共享一次模型语义调用供两个下游使用，避免将两次随机解析差异混进规划比较。成本必须拆semantic与planning token，不能当两个独立重跑结果。rule无需模型，oracle无需模型。JSON输出模式关闭，严格whole fence解码；禁止多余字段、重复键、截断。quote仅证明原文存在，不保证语义正确或完整。

规划v6不再包含固定“黄先蓝后五步答案”的提示，只提供当前持物依赖与临时释放的一般规则，明确pick不含任何target_id。保持1024tokens，不通过自动删除非法target字段提高结果。当前输出只做符号检查，拒绝不带部分物理授权。

## 指标和结论边界

按三个子集分别报告semantic exact、gold-plan/constraint success、严格端到端成功、有效拒绝、schema/quote错误和误接受。模型契约错误但在线校验通过，记misaccept；可执行任务被澄清，算覆盖失败但不同于危险执行。故障保留全部分母，独立评分不纠正在线契约。

禁止合并ready与refusal写成机器人成功率。配对对照按相同指令，先报both/model-only/rule-only/neither；24条pilot不靠显著性宣称通用模型必要性。规则在受控语法胜出/持平应如实保留，模型在自由措辞高分也只能证明该小集的适配，不代表开放世界。

## 执行预算和后续

一次24条，最多48模型调用，API timeout60秒、内部重试0。不自动补跑失败、不按成绩改模型或选择性扩大。完成后先分析失败再决定独立正式集与持续场景子集。物理集需重新绑定任务/观测版本与持物/释放证据；本轮不能直接下发控制。
