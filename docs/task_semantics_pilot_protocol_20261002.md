# 任务语义变化 pilot v1

## 目的与边界

从先前固定“蓝放回桌面、黄放绿区”的任务更新，扩展到取消、对象变化、当前持物指代、禁止动作、放置顺序、歧义与对象缺失。12条中英文指令、6组语义类型，10条可执行、2条应拒绝。不将12条称为正式泛化证据；指令与标注为开发者构造，需在pilot之后另冻结独立措辞和任务组合的正式集。

本轮为**语义解析与符号计划诊断**，没有新增物理仿真。图像复用既有持续场景蓝块持物时的帧；对象目录是已知颜色候选，持物关系是显式fixture，不是这轮新视觉估计。不能据此声称开世界、视觉状态估计或连续执行成功。

## 信息隔离

- 解析输入：原始新指令、图像、候选目录、当前fixture事实、旧目标、通用契约schema。
- 解析输出：新最终位置目标、禁止未来动作的对象、目标放置顺序、空手要求或澄清/不支持状态。
- 计划输入：仅解析契约与共享当前状态/技能，无人工正确目标。
- 人工gold仅在离线评分与明确标记的oracle语义搜索对照使用，不会纠正在线模型契约。
- 历史蓝色pick已完成；生成的是剩余动作，不允许重放历史。
- 澄清或不支持不得携带部分可执行目标；不把缺失对象换成其他颜色。

## 对照与指标

1. 模型语义解析 + 模型剩余规划：新增端到端流程。
2. 同一模型语义解析 + 通用确定性搜索：区分错误发生在语义层还是规划层。
3. 人工正确语义 + 相同确定性搜索：oracle上界，不冒充自然语言规则基线。

搜索统一使用两个可操作对象、pick/place注册技能、table/green_region目标、深度6；不写每case答案，完整输出仍经Validator、目标与轨迹约束检查。搜索前缀允许手中持物，不能因完整计划检查不允许终态持物而提前剪掉合法pick前缀。

分别报告：契约精确匹配、10条可执行指令的符号任务/约束成功、2条拒绝正确性、禁止/顺序违反、基于错误语义的误接受、调用/token以及基础设施缺测。禁止动作检查整条未来轨迹，不能仅靠最终状态回到桌面。顺序只针对首次达到指定目标的放置动作；不是通用时序逻辑。空计划仅在当前状态已满足目标时通过。

有限12条pilot没有显著性或LLM必要性的正式结论；高分只说明该受限契约能够表达这些指令。模型与搜索等效时须如实报告，并将模型价值限定为自然语言到结构化任务接口。后续规则解析基线须明确支持语法和拒绝率，不能故意只支持一句旧模板。

## 后续关卡

1. 检查所有失败/语义误接受，确认不丢禁止与顺序要求。
2. 冻结未调参的新措辞/组合、共享候选与观测信息；补透明规则语义解析对照。
3. 接持续物理场景中的可执行子集：取消、持物指代、禁止黄色、蓝回桌面后黄去绿区。双块同一绿区与逆序涉及控制容量/碰撞，先验证后端，不直接批跑。
4. 复用现有任务/观测版本绑定与有界再观测门控；不要将符号许可直接变成物理执行授权。
