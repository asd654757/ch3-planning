# 任务语义 pilot v1：失败诊断，非正式性能证据

原始目录：`data/collections/task_semantics_pilot_20261002_185050`。12条全部完成，无物理执行、无自动重跑。契约严格精确匹配0/12；人工契约下完整计划与约束通过3/10（持物指代、蓝放绿区且禁止黄色、蓝先黄后）；应澄清/不支持的2条均误判ready，正确拒绝0/2。**不能把精确匹配0/12直接解释成所有任务均执行失败**，这里未进行物理执行，部分契约冗余顺序或空手字段错误但计划仍满足gold。

## 故障定位

- 取消/返回类：漏掉blue→table，只剩hand_empty；其生成放绿区的动作可通过错误契约，却不满足用户目标。
- 对象切换类：漏掉持物蓝块的返回目标，直接pick yellow引发状态冲突。
- 持物蓝去绿区：位置正确，但错误填hand_empty=false，并凭空增加单对象顺序。
- 禁止类：部分禁止字段正确；仍可能将table错误恢复为旧green目标。
- 逆序类：解析出了yellow先blue后，但生成计划违反顺序；轨迹顺序检查拒绝了它。
- 歧义与缺失对象：把未知语义静默替换成旧blue→green目标，暴露语义误接受。

这轮没有证明模型必要性，也未证明任务语义适应已经完善。它定位了一个真实前端缺口：形式合法与正确理解指令是不同问题。人工契约的通用搜索10/10可解；模型解析后搜索用于区分语义层与计划层，不冒充规则自然语言基线。

## 数据口径与预算

原冻结manifest写max_calls=22是预算估计错误：预期2条拒绝不再调用规划，但错误解析ready后也调用了规划，实际24次。保持原manifest不改写；后续脚本上界修正为24。所有原输出/失败留存，不能只挑3条通过样本进入论文。
