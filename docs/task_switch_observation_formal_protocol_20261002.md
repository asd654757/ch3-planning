# 持续场景任务切换与有限再观测：正式协议 v1

## 为什么现在可以扩量

受控黄色持物时的目标区域遮挡导致在线绑定歧义。修正不是放松识别，而是最多2轮固定开销的闭手上移/共运动再观测。每次移动后重新确认持物；目标仍未知则停止。上移是固定工作区内启发式，不是运动规划器的碰撞安全证明。状态/图像新版本用于下一动作，历史成功不当作当前效果。

真实seed1机制诊断：1次额外观测后完成，2模型调用、549控制步。原始输出目录 `task_switch_reobserve_20261002_v1_seed1`。不将这个开发样本混进正式集。

独立pilot `task_switch_observation_pilot_20261002_v1` 完成15/15：
- 规则+观测：3/3成功，3模型调用合计。
- 当前状态重规划+观测：3/3成功，6调用合计。
- 当前状态重规划、无额外观测：2/3成功，6调用合计。
- 持续目的区域观测黑屏：规则3/3、重规划3/3停止且无黄色放置；分别3/6调用合计。

此结果不证明VLM优于规则，也不证明普遍成功。协议扩量gate检查完整记录、预算、reset、动作历史、缺失反馈下禁止放置、运行代码哈希；**不以成功率阈值筛选任务**。`scale_gate.json` 已通过。pilot 3seed只验证可行性。

## 正式集

30个scene seed，每seed以下5次：
1. 规则恢复+有限再观测；
2. 当前状态重规划+有限再观测；
3. 当前状态重规划、无额外再观测；
4. 规则恢复+持续目的区域反馈缺失；
5. 当前状态重规划+持续目的区域反馈缺失。

合计150次任务运行，**不是150个独立任务模板**。seed只改变对象允许的位置；前三种设置按seed轮换执行顺序。30seed中包括pilot的0–2，正式独立重新调用，不冻结/复用模型输出；必须披露pilot已使用这三个布局进行可行性检查。正式不改prompt或阈值，不按失败原因选择性补跑。

同一任务内四动作在同一episode，只有初始reset；相同后端与800步上限，最多2轮再观测，每case wall timeout240秒。当前状态重规划通常2次VLM调用（初始计划+更新后计划），规则通常1次（共享初始模型计划）。调用/成本单列。模型参数继承客户端qwen-vl-plus、温度.1、解码seed0、max_tokens1024，外部任务是脚本明确的任务更新，不是自然语言目标解析实验。

## 主题和能力边界

这是规划与恢复主题下的**持续场景任务更新、观测感知后缀执行及拒绝**评估。不是整个ROUTED框架正式总评，不同时验证早期超时、任意任务解析、开放世界或自然失败分布。不训练动作模型，不改变固定控制器的可替换后端定位。

候选来自有限已知颜色；初始空手与桌面状态是fixture；黄色未被触碰仍在桌面是fixture前提。持物和释放依靠局部RGB/机械臂共运动证据。区域定位依赖已知平面与可见外缘。目的区域黑屏只作用于目的绑定观测；期间仍可用独立未屏蔽的持物probe帧，这是选择性的目标可见性扰动，不是整个感知通道完全失效。

真值只有最终独立评分，不用于在线绑定、手状态或修复。安全停止是系统保守拒绝，不是绝对物理安全保证。

## 分析要求

- 正常任务90次与缺失反馈60次分开；缺失条件预期停止，不和正常任务混算平均完成率。
- 每方法正常分母30；规则/重规划共享seed配对。额外观测消融配对比较同seed两种重规划设置。
- 启动后解析拒绝/协议错误/执行失败全部留在分母，基础设施缺测单列；不补跑后只保留成功结果。
- 每个case保留模型raw、token、图像、观测原因、动作trace、在线事实/剩余目标和独立评分。
- 缺失条件同时报告是否进入实际目的观察阶段；前端拒绝不能单独当成“黑屏检测成功”。所有实例无放置率可附报。
- 使用seed配对统计与置信区间，seed重复设置不是独立样本；不将多个控制步骤当任务样本。
- 重点比较无额外观测和有限观测在何种遮挡条件有差异。规则与模型同分应报告成本，不能归因于LLM必要性或路由 superiority。
- 控制步、再观测次数、token与模型调用成本一起报告，恢复能力/拒绝可靠性/效率分别归因。
