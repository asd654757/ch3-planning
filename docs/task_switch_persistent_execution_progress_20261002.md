# 持续场景任务切换：执行接入与有限 pilot

## 实际完成

新增 `scripts/task_switch_execution_smoke.py`。一次 episode 中抓蓝色，然后外部指令更新为返回蓝色并运输黄色到绿色区域。接入任务版本与观测账本；同一固定控制后端，恢复过程中没有 env.reset。符号 `table` 的本实验实现明确映射为**可见紫色返回子区域**，不使用仿真真值生成目标坐标。

- 黄色/紫色已加入受限 RGB 候选定位。多个距离较远的同色块拒绝；抓手将单个色块遮成相邻碎片时，3px内 bbox 间距归组。相邻同色物体仍可能混淆，所以不是通用对象身份识别。
- 平面标记定位先将颜色像素投到假定平面，再取世界坐标范围中心，避免直接取图像 bbox 中心的透视偏差。平面、区域静止、外缘可见是建模前提，不是深度/接触估计。
- `visual_release.py` 在已经支持的单物体持有前提下，要求开手撤离完成、物体静止、手移动且分离、RGB估计到达目的地，才给出局部释放/空手支持。黑屏返回 unknown，不能抓黄色。不是通用空手或碰撞安全证明。
- 蓝色返回后，下一段 plan 从新观测支持的状态重新校验。黄色持有时若蓝色区域被遮挡，不把历史蓝色成功写为当前事实，也不阻止前置条件已支持的黄色放置。最后重新观察蓝色位置，才能关闭其剩余目标。
- 完成 waypoint 不代表 grasp/place 成功；独立真值评分仅在全部在线决策结束后读取。
- 这个运行器实现**任务切换路径**，不是完整初始自然语言解析或所有 ROUTED 分支都已统一接入。初始/更新指令由脚本给定；初始手空、黄色尚未触碰在桌面是受控前提。用于验证规划与恢复主题，不替代开放世界感知。

## 已准备的有限 pilot

`run_task_switch_execution_pilot.py`：3个seed × 规则恢复/当前状态重规划两种设置=6次，加seed0释放反馈黑屏规则设置=1次，总7次。规则方法拿相同新任务和观测；所有设置共享初始模型规划、反馈门控、固定后端、800步上限。交替设置顺序。每任务240秒wall timeout，无自动失败样本选择性重跑。

启动前写manifest（代码commit、运行器SHA、seed、设置与预算）；逐任务独立日志和summary；缺summary/超时也计入records。调用数与task次数分开。规则正常1次模型调用，直接重规划正常2次；协议不存在单凭增加调用便声称路由贡献。

后台启动后只确认一次正在实际执行，然后停止实时监控。pid/log/output路径写 `/tmp/task_switch_execution_pilot_{pid,log,output}`。结果不是正式benchmark，尚不能和旧321点等合并。

## 转正式的门槛

需检查7次记录完整、物理目标与在线估计误差、黑屏不触发黄色抓取、0恢复reset、无历史pick重放；失败不应选择性删除。若受限后端仍有系统性无法执行的路径，先修复并新版本pilot。规则同样成功是合理结果，不能故意削弱基线。

正式方案的5条件及完整自适应比较设置还未全部接入此运行器；因此不从这7次自动启动150次正式实验。后续先统一早期超时、无扰动、有限再观测和任务切换的实际执行入口，再冻结manifest及分析方案。
