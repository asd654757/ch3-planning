# 持物期间任务更新：剩余动作序列变化诊断

## 主题与范围

这是任务规划/恢复接口的扩展，不扩控制器训练或通用视觉检测。限定候选为蓝色方块、黄色方块、绿色区域；初始状态为右手持蓝色、黄色在桌面、区域在桌面。当前事实明确给定，**不是本轮从图像估计得到**。

外部命令更新为：取消尚未执行的蓝色到绿色放置，改为将黄色运至绿色，并将已持有蓝色放回桌面。任务更新由脚本明确给定，不是模型自然错误或执行失败；该场景与未知对象压力测试必须分开描述。

新接口 `task_switch_recovery.py` 严格解析动作字段、验证当前状态、检查两个最终目标与手空、限定剩余三动作范围，然后编译。不会授权物理执行，也不自动替换未知对象。

同一状态下两个明确标为手写控制的结果：

- 沿用旧 place blue→green：结构合法，但更新目标不满足，拒绝。
- 手写先放蓝色再运输黄色：合法且目标满足。它说明规则也能解决这个有限案例，不能宣称大模型在准确符号输入下不可替代。

相关测试 104 项通过。包括遗漏释放直接 pick 导致非法、旧后缀合法但目标错误、额外字段/未知对象/不支持状态拒绝。

## 本轮没有完成的事

没有新建或运行物理仿真 episode；没有实际释放蓝色、抓取黄色或验证最后放置；没有新的端到端完成率。compile 成功不表示底层已具备安全执行能力。

当前 table 是符号特殊目标，不是一个已视觉定位的放置区域。现有控制器要求可执行位置绑定，因此不能直接执行这个 table 步。黄色候选图像定位、桌面释放位置绑定、阶段完成证据，以及动作后新观测/剩余任务更新还需补齐。

## 下一步与比较规则

1. 明确受控桌面释放区域并建立可审计的绑定，不用模拟器真值提供位置；允许记录固定场景假设，但不冒称视觉估计。
2. 将已有黄色对象纳入有限颜色候选接口，检查与蓝色、绿色的歧义/缺失；不训练通用检测器。
3. 逐步执行，阶段失败停止，独立评分与在线判断分开。只有这条持续链路成功后才跑少量 seed 对照。
4. 比较旧剩余计划、确定性释放再运输规则与当前状态模型规划。各设置收到相同更新指令、状态和对象绑定，不能故意不通知基线任务变化。

此例用于说明“旧计划结构合法不等于新任务可用”以及当前状态对剩余动作依赖的作用。任务切换不能代替自然故障恢复证据；规则若同样强，则据实报告，模型价值仍需自然语言指令解析与状态不确定性条件支持。
