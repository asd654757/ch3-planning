# 易廷昊博士论文阅读：大模型规划设计与实验借鉴

阅读对象：《面向工业配料场景的机器人任务规划与作业关键技术研究》，中国科学技术大学工程博士论文，封面完成时间 2026-05-26。阅读日期：2026-11-12。

主要核对第 4 章（正文 53–70 页，PDF 68–85 页）、第 6.3.2 节及第 6.4.2、6.4.4 节。以下“论文报告”与“针对 ROUTED 的建议”分开陈述。本文不是对原始实验记录的独立复现。

## 1. 最值得借鉴的总体设计

论文第 4 章的规划器不是直接让大模型输出机器人关节动作，而是将大模型用于生成、分解和修正规划模型，再结合符号求解和验证。

```mermaid
flowchart LR
    A[任务指令与场景图] --> B[生成领域与任务相关子图]
    B --> C[生成问题描述与子目标]
    C --> D[符号规划器与大模型规划器]
    D --> E[验证候选计划]
    E -->|有效| F[执行与状态更新]
    E -->|失败诊断| G[修正领域或问题描述]
    G --> C
```

图 4.2（正文 55 页/PDF 70 页）是最值得精读的框架图。第 4.2.2–4.2.7 节分别说明六个环节：

| 环节 | 论文实际做法 | 对 ROUTED 的借鉴 |
| --- | --- | --- |
| 领域生成 | LLM 生成 PDDL 类型、谓词、动作及其前置条件/效果 | 将自然语言推理产物与执行能力接口明确分离；执行器真实能力不能因规划失败而被 LLM 任意改写 |
| 场景图剪枝 | LLM 提取任务相关物品，保留房间和相关关系 | 研究依赖相关对象/历史片段的选取，而不仅是关键词匹配；不能裁掉阻挡物、禁止操作对象等关键条件 |
| 问题生成 | 生成对象、初始状态和目标的 PDDL 问题 | 区分观测事实、模型推断和用户要求；不能把动作回执直接填成已完成事实 |
| 目标分解 | 按动作前置条件和效果组织有序子目标 | 用承载能力、资源释放、访问顺序等真实约束构成任务难度，而不只是增加文本长度 |
| 多规划器 | FastDownward 和 LLM 分别生成候选，验证后选有效计划 | 这是可借鉴的组合策略；需要检验是否有互补错误，以及优势是否只是来自更多计算预算 |
| 反馈修订 | 按错误类型修订领域 D 或问题 P，再分解和求解 | 比统一提示“重试”更具体：应让反馈指向错误来源，并限制对应修改范围 |

论文的反馈报告为 `(错误类型, 涉及实体, 自然语言解释)`，例如缺少谓词、不可达状态、领域错误、目标冲突（正文 60 页/PDF 75 页）。其中有选择地更新 D/P 是主要方法设计之一。

第 4 章使用未微调的基础 LLM；这不意味着整篇论文的系统“零训练”。第 5 章训练动作模型，第 6 章工业语义部署还涉及 CLIP 的领域适配。用户若继续零训练集成，主要借鉴第 4 章的规划框架，不需要复刻全部感知与动作训练研究。

## 2. 可以借鉴、但不能直接当作新贡献的内容

结构化提示、任务分解、LLM+PDDL、验证器反馈、多规划器、根据失败修改规划模型，已经出现在这篇论文的方法中。因此再次把这些模块串起来，不足以直接证明 ROUTED 的新颖性。

论文采用 LLM 建模与符号规划组合，也说明应区分“自然语言/开放信息解释”和“已形式化任务求解”。未来面向生成式模型，并不自然排除后者作为比较对象。

另一个关键边界是：VAL 检验给定 PDDL 模型中的计划有效性，并不独立证明 LLM 生成的目标完整表达用户要求，或其动作前置条件符合真实机器人。多个规划器也可能共同依赖同一个错误模型。论文报告的验证层不能被自动理解为真实世界正确性的完整证明。

对 ROUTED 更值得考察的候选问题是：**哪些模型内容可以被何种证据修订，以及如何保持未经授权修改的要求与执行历史。** 例如：

- 建模错误：修订有证据支持的谓词或动作前置条件。
- 世界变化：基于新观测更新当前事实，保留观测来源和时间。
- 用户改任务：生成新的要求版本，保留未改部分和相应生效边界。
- 执行能力失败：更新该技能当前是否可用，或停止并请求帮助；不能用删除真实物理约束来“修通”计划。

这是从论文得到的研究启发，不是已经证实的新颖性。当前 ROUTED 的引用原文检查只说明引文存在，并不证明该引文支持某个编辑；也不能以已有历史消融替代与标准模型修订方法的对照。

## 3. 论文的实验设置

### 3.1 公开规划任务：第 4.3.1–4.3.2 节

正文 61–65 页/PDF 76–80 页：

- 使用 3DSG 测试场景，四类任务：电脑组装、餐桌布置、房屋清洁、家庭办公。
- 三个场景：Allensville（11 房间、42 物品）、Parole（7 房间、31 物品）、Shelbiana（12 房间、34 物品）。
- 机器人一次携带一件物品；清洁任务存在严格先后关系，办公任务涉及先打开家具再取物的依赖。
- 每个任务与场景组合重复 50 次；文中将完整配置写为 4×3×50=600 次。不能据此直接推出所有模型、消融及对照的总调用数。
- 分别考察未分解原任务和分解后的任务。
- 基线：LLM-As-Planner、LLM+P、LLM-GenPlan、SayPlan、DELTA。
- 本方法基础模型：DeepSeek-V3-0324、Qwen3-235B-A22B-Instruct；temperature=0、top-p=1，无微调。
- FastDownward 与 LLM 生成候选动作计划；使用 VAL 验证，并在 PDDLGym 中验证执行；每规划器每子问题 60 秒。

更值得借鉴的是表 4.2 的同基础模型比较。表 4.1 包含不同模型版本的既有方法，正文也承认基础模型差异可能影响结果；不能把混合模型大表的差异全部归因于规划方法。

可借鉴“具体机制必须对应可移除模块及可测量结果”。但这是累计删除，不能直接解释成每个模块在其他模块均开启时的独立收益。ROUTED 若只主张两个核心机制，应分别单独删除，并报告必要的交互对照；不必给所有工程组件都冠以创新名义。

### 3.3 商超与遮挡恢复：第 4.3.4 节

正文 67–69 页/PDF 82–84 页：

- GR-3 取货、R2V2 理货两个任务，每方法每任务 20 次；自优化最多三次。
- 表 4.4 中本方法 DS 的两项成功率为 100% 和 85%；DELTA DS 为 100% 和 55%。
- 实验明确只统计规划层成功率，操作员检查计划；计划可行但低层能力失败时，可遥操作完成。故这些数值不等于没有人工介入的端到端执行成功率。
- 工业遮挡案例手工给两个方法相同的不良初始计划：先抓被遮挡的 QR005，再抓上方 QR003。十次重复中，无反馈方法仅两次依赖下游技能完成；有反馈方法报告十次完成。

这个遮挡实验能说明有反馈相对无反馈在该设置下的作用。它不能直接证明有反馈方法优于“获得同样失败信息的直接重规划”。ROUTED 的研究一直关心后者，因此应保留这一强对照。

### 3.4 工业任务难度：第 6.4.2 节

正文 110–111 页/PDF 125–126 页：四套双层货架、18 个放物料的料框，设计八类任务，各重复 20 次，统一使用私有部署 Qwen3-32B。

任务难度从单物料、单位置扩展到同一物料分散在多个料框，需要跨位置凑齐数量。例如 QR008 分布在三个料框，每框一件；取两件不能反复对同一料框取用。数量和位置由人工确认，场景每轮人工恢复。

该组规划实验假定移动成功、非明显不可行动作成功，目的是隔离规划能力。表 6.2 中本方法任务 1–3 为 100%，任务 8 为 15%；DELTA 任务 8 为 0%。应借鉴真实约束引起的难度变化和对能力边界的报告，不是刻意找让基线失败的表述。

### 3.5 系统集成：第 6.4.4 节

正文 113–116 页/PDF 128–131 页：30 组实际工单，每组每方法三次；工单要求 3–12 种物料、每种 1–3 件。分别统计规划、物料操作与整个工单完成情况。

表 6.4 报告规划成功率 65.5%→97.8%，操作成功率 37.9%→93.1%，整体任务 14.4%→84.9%。由于规划与低层操作方法同时改变，整体增益不能全部归因于规划算法。ROUTED 若研究规划机制，应固定同一执行器；若展示整套系统升级，需另设规划器×执行器组合来区分来源。

表 6.5 报告平均规划耗时 LLM+P 为 24.6 秒、本方法 31.5 秒。论文承认额外重规划增加耗时。这说明研究可以讨论正确性与开销的权衡，但应补齐相同预算或成功率—预算曲线，不能默认多次尝试的收益全是算法收益。

## 4. 针对 ROUTED 的可执行借鉴顺序

1. 固定规划模块的接口：任务要求、可用技能、当前有证据的状态、执行历史、失败反馈分别记录。保持现有 MuJoCo 执行能力，先验证方法差异。
2. 区分并限定修订对象：建模错误、世界事实更新、用户要求变更、技能能力变化分别处理。模型修订后检查未改要求及历史语义，不能只验证新模型内存在一条计划。
3. 选取真正改变决策的任务机制，例如跨容器补足数量、必须先移开阻挡物、已完成部分随后发生需求修订、旧事件证据不足、技能持续失效。任务来自目标应用；所有方法获得同样的事实、历史和能力信息。
4. 对照保留同信息直接反馈重规划、完整重译加标准历史监控/求解，以及完整 ROUTED。分别报告方法之间共享了哪些模块，避免把共同历史检查器的效果归给编辑格式。
5. 主指标区分规划有效性、任务完成、修订语义保持、错误继续执行、冲突识别和必要澄清；补充调用/token、重试次数、时间与控制步数。正确暂停不能算作物理任务完成。
6. 冻结开发/测试案例及预算，先做机制诊断，再增加实例与重复。任务数和重复数分别报告，不能把同场景 50 次当作 50 个独立场景。

## 5. 复现或引用时需要补问清楚的地方

- 正文 59 页说至少一条有效计划即可选择，61 页又说至少两个规划器均成功且核心流程一致；这两种接受规则不同，复现应明确采用哪一种。
- 第 4 章给出统一模型推理参数和每子问题求解时限，但未完整展示所有方法相等的总调用/token 预算；方法效果与预算效应应分开。
- 反馈式模型修改需要校验用户目标、事实和机器人真实能力是否保持。本文的描述没有充分建立对这些内容全部保持正确的形式保证；不能将模型内验证直接写成真实世界正确性。
- 第 4 章认为初始剪枝后场景图在优化中保持不变。正文 69 页也承认建图缺失、技能持续失败和反复重试等限制。因此它不是已经解决通用开放世界在线变化的方法。
- 第 5 章的 LIBERO/Meta-World 主要验证动作专家训练。它们与第 4 章的 3DSG/PDDL 规划实验职责不同，不能因为论文使用了 LIBERO 就将其认定为本研究的必要规划平台。

适合优先借鉴的是：结构化建模、失败来源定位、约束驱动的任务难度设计，以及分层实验。研究独立贡献仍需与已有模型修订、时序监控和同信息反馈重规划方法核验；本阅读不改变当前“增量方案独立优势尚未建立”的结论。
